## 新增
- **内置 Perforce。** termide 自带一个 Perforce 插件：无需 Python，无需下载，在 Linux、macOS 和 Windows 上表现一致；只需 `PATH` 中有 `p4`。在全局配置为它指定模式之前（`[plugins.perforce]` 中设 `mode = "on"`，或设 `"opt-in"` 并在项目的配置文件中设 `enabled = true`），它一直处于休眠状态，因此仅有一个仓库永远不会唤醒它；它始终是一个独立进程，只在需要它的项目中启动。它在状态栏中显示编辑器中文件的状态（`p4: #3/5 (out of date)`、`edit · change 1234`、`locked by …`）；当 `Ctrl+E` 在只读文件中开启编辑时，将其打开以供编辑，若别人已打开该文件则先询问（也可从命令面板将其打开以供添加）；当 `Ctrl+E` 再次关闭编辑时，提议还原该文件，并询问是保存还是丢弃未保存的更改；在 git 之外的项目中按 `Alt+G`，按变更列表在文件夹树中列出已打开的文件，其中 `Enter` 打开文件，`F3` 在 git diff 面板中显示其差异，`Backspace` 还原它，`Space` 列出可对它执行的操作，在变更列表上按 `Enter` 则提交它——默认变更列表通过一个对话框提交，其中包含描述和要提交的文件；它还能从命令面板显示文件的差异，在终端中同步，并为智能体提供 `opened`、`diff` 和 `edit` 工具。它在文件管理器中为已打开的文件着色，并在编辑器的边栏中标出相对于仓库（depot）已更改的行，就像 termide 对 git 所做的那样。插件目录中同名的插件会取代它。
- **插件可以显示其他版本控制系统的状态。** `files/status` 用 git 的颜色（`modified`、`added`、`deleted`、`ignored`）为文件管理器中的文件着色，包括已更改文件上层的各个目录；`editor/base` 提供编辑器用来标记已更改行的基准文本。`file/will_edit` 把对磁盘上只读文件按下的 `Ctrl+E`，以及对已保存的可写文件再次关闭编辑的操作，先交给插件处理，这样插件可以签出或还原该文件，并让未保存的工作得到保存或丢弃，而不是由编辑器绕过文件权限。带有 `"replaces": "open_git_status"` 的命令会在 git 之外的项目中响应 `Alt+G`。两者都以 git 优先：只在 git 无话可说的地方才补充，例如仓库之外。插件的面板可以是 `list` 而不是 Markdown：若干组行，每行带有各自的操作，用 git 状态的按键在其间移动和执行，带路径的行组成文件夹树，下方还有按钮；也可以是 `diff`，即一个统一差异，显示方式与 git diff 面板显示 git 差异相同。`window/dialog` 在一个窗口中进行询问，窗口可由一条消息、一个单行或多行文本字段、一个可供阅读、选择或勾选的列表，以及最多六个按钮组成。
- **API 密钥存入密码保险库。** AI 设置中连接的页面有一个 **API 密钥** 字段：在此输入的密钥以掩码显示，以连接名称存入加密保险库，从不写入 `config.toml`，字段只显示是否已存储密钥。由 `api_key_env` 指定的变量仍然优先。若请求的密钥位于已锁定的保险库中，会要求输入主密码；若取消，请求会失败并说明原因。重命名连接会移动其密钥，删除连接会移除其密钥。若把密钥而不是变量名粘贴到了 `api_key_env` 中，它会显示为 `********` 并附带警告，在 **API 密钥** 字段中选择一项即可将其移入保险库。从命令行运行时无法解锁保险库，需要使用 `api_key_env`。
- **谁花掉了会话的令牌。** 智能体面板的会话信息（`F3`、`/usage`）按花费者细分会话的令牌——对话、子智能体、`auto` 审查者、`recall` 的求解器、摘要、`/goal` 评判者、`/handoff`，以及 Claude Code 在其内部为自己的子智能体、摘要和辅助调用所花费的部分——并按模型细分（子智能体的数据从其自己的会话日志中读取，包括其审查者），每项都带有一个条形图及其所占令牌份额，所有类型的令牌都按同等计数；同时显示缓存提供的提示令牌所占份额，以及在提供商单独统计时（Codex、OpenAI 兼容服务器）用于推理的输出。它还显示上下文的构成——系统提示、工具定义、技能、工具输出、对话、摘要，以及 CLI 智能体在这些之外自行持有的内容——以及每个工具在整个会话中的结果（技能按名称列出）：它们为上下文带来了多少内容，以及模型在其后的调用中又重新读取了多少。这些数据来自会话日志，因此重新打开的会话也会显示它们，状态栏的总计从会话已有的花费开始，而不是从零开始；分叉则从其自身的起点开始计数。

## 修复
- **重新打开的智能体会话会显示其上下文的占用程度。** 过去重新打开会话或重启 termide 后，无论自上次摘要以来上下文中有多少内容，在下一次回复之前都显示为 0；现在 Claude Code 或 Codex 会话的占用量和窗口大小会保存在其日志中，内置智能体的则从其最后一次调用中读取。
- **重新打开的智能体会话会显示完整的对话。** 过去重新打开会话或重启 termide 后，只显示上一次压缩在上下文中留下的内容——冒充你第一条消息的摘要和保留下来的少数几条消息——尽管实时面板曾显示全部内容，日志也完整保存了一切。现在面板会显示该分支上的每个块，并在压缩发生的位置显示压缩提示，与运行时的显示一致；模型的上下文保持不变。
- **Claude Code 或 Codex 审查者的令牌会被计入。** 过去交给 Claude Code 或 Codex 的 `auto` 模式审查者、`recall` 的求解器和目标评判者报告的花费为零，因此会话总计遗漏了它们——约占 termide 驱动的 Claude Code 花费的三分之一。现在它们会被计入，记在调用所用的模型名下，包括被智能体停止或拒绝的调用。
- **退出编辑模式时会询问未保存的更改。** 过去在有未保存更改的文本编辑器中按 `Ctrl+E` 或点击 `Edit: Yes`，会切换到查看模式并把更改留在缓冲区中；在十六进制编辑器中，编辑会在看不见的地方继续挂起，因此之后关闭视图可能会悄无声息地丢失它们。现在两者都会先询问：保存并查看、丢弃更改并查看，或取消并继续编辑。
- **打开的文件会跟随其写入权限。** 过去在没有写入权限时打开的文件，在 `p4 edit` 或 `chmod +w` 使其变为可写之后，在编辑器中仍保持只读，直到按下 `Ctrl+E` 或重新打开它——这是 Perforce 用户遇到的第一个问题，因为 Perforce 在签出之前会让文件保持只读。现在，当文件在磁盘上发生变化以及折叠的面板被显示时，编辑器会重新检查权限：变为可写则可编辑，再次变为只读（`p4 revert`）则变为只读，但有未保存的工作时除外。`Ctrl+E` 仍然可以覆盖该模式，直到权限下一次变化；以仅查看方式打开的文件保持只读。
- **自定义命令文档中的 `p4 edit` 示例** 过去绑定的是 `Alt+E`，而它会打开一个新编辑器，因此该命令从未能通过键盘运行；现在它绑定的是 `Shift+F5`。
