## 新增
- **内置 Perforce。** termide 自带一个 Perforce 插件：无需下载，在 Linux、macOS 和 Windows 上表现一致，只需 `PATH` 中有 `p4`。它默认关闭，可在 设置 → **插件** 中开启，或在全局配置的 `[plugins.perforce]` 中设 `mode = "on"`；设 `mode = "opt-in"` 则交由各个项目决定，项目在其 `.termide/config.toml` 中设 `enabled = true` 即可开启。状态栏会显示编辑器中文件的状态：`p4: #3/5 (out of date)`、`p4: edit #5/5 · change 1234`、`also opened by …`、`locked by …`、`not in depot`。在只读文件中按 `Ctrl+E` 会将其打开以供编辑：若别人已打开该文件则先询问，若文件已被锁定则拒绝；在你已打开的文件中关闭编辑时，会询问是保持打开还是还原它，若有未保存的更改，还会询问是保存还是丢弃。在 git 之外的项目中按 `Alt+G`，会按变更列表在文件夹树中列出已打开的文件，按键与 git 状态相同：`Enter` 或 `F4` 打开文件，`F3` 在差异面板中显示其差异，`Backspace` 还原它，`Space` 列出可对它执行的操作，在变更列表上按 `Enter` 则提交它——默认变更列表通过一个对话框提交，其中填写描述和要提交的文件。命令面板可以将新文件打开以供添加、显示文件的差异，以及在终端中同步工作区。已打开的文件在文件管理器中显示相应颜色，相对于仓库（depot）已更改的行会像 git 一样在边栏中标出，智能体还会获得 `opened`、`diff` 和 `edit` 工具。插件目录中同名的插件会取代它。
- **插件可以代替其他版本控制系统。** `files/status` 用 git 的颜色为文件管理器中的文件着色，包括它们上层的各个文件夹；`editor/base` 提供边栏用来标记更改的基准文本。两者都以 git 优先，因此只在 git 无话可说的地方才补充。`file/will_edit` 把 `Ctrl+E` 先交给插件处理——无论是在磁盘上只读的文件中开启编辑，还是在可写文件中关闭编辑——这样插件可以签出或还原该文件，并让未保存的工作得到保存或丢弃。带有 `"replaces": "open_git_status"` 的命令会在 git 之外的项目中响应 `Alt+G`。插件的面板可以是 `list`——若干组带有操作的行，用 git 状态的按键执行，带路径的行组成文件夹树，下方还有按钮——也可以是由差异面板显示的 `diff`。`window/dialog` 在一个窗口中进行询问，窗口由一条消息、一个文本字段、一个可供选择或勾选的列表，以及最多六个按钮组成。
- **API 密钥存入密码保险库。** AI 设置中连接的页面有一个 **API 密钥** 字段：在此输入的密钥以连接名称存入加密保险库，从不写入 `config.toml`，字段只显示是否已存储密钥。由 `api_key_env` 指定的变量仍然优先。若请求需要的密钥位于已锁定的保险库中，会要求输入主密码。重命名连接会移动其密钥，删除连接会移除其密钥。误粘贴到 `api_key_env` 中的密钥会以掩码显示并附带警告，一步即可将其移入保险库。从命令行运行时无法解锁保险库，需要使用 `api_key_env`。
- **谁花掉了会话的令牌。** 智能体面板的会话信息（`F3`、`/usage`）按花费者细分令牌——对话、子智能体、`auto` 审查者、`recall` 的求解器、摘要、`/goal` 评判者、`/handoff`，以及 Claude Code 在其内部所花费的部分——并按模型细分，同时显示缓存提供的份额，以及在提供商报告时用于推理的输出。它还显示上下文的构成——系统提示、工具定义、技能、工具输出、对话、摘要，以及 CLI 智能体自行持有的内容——以及每个工具的结果在留在上下文中期间的花费。这些数据来自会话日志，因此重新打开的会话也会显示它们，状态栏的总计从会话已有的花费继续累计，而分叉只计算它自己的花费。

## 变更
- **Claude Code 和 Codex 用最便宜的模型进行审查。** 过去在未指定审查者时，Claude Code 或 Codex 会话的 `auto` 模式审查者运行在会话自己的模型上（通常是前沿模型），约占 termide 驱动的 Claude Code 花费的三分之一。现在它运行在 CLI 提供的最便宜的模型上——Claude Code 为 Haiku——若 CLI 未提供则使用会话的模型；在 `[ai.auto_reviewer]` 中或连接上指定的审查者仍然优先。它的调用还改用 Claude Code 的五分钟缓存，而不是价格高一倍的一小时缓存。

## 修复
- **重新打开的智能体会话会显示完整的对话及其上下文的占用程度。** 过去重新打开会话或重启 termide 后，只显示上一次压缩留下的内容——冒充你第一条消息的摘要——并且在下一次回复之前上下文显示为 0。现在面板会显示每个块，并在压缩发生的位置显示压缩提示，上下文的占用程度也与当时一致。
- **Claude Code 或 Codex 审查者的令牌会被计入。** 过去在 Claude Code 或 Codex 上运行的 `auto` 审查者、`recall` 的求解器和 `/goal` 评判者报告的花费为零，因此会话总计遗漏了它们。
- **退出编辑模式时会询问未保存的更改。** 过去在有未保存更改时按 `Ctrl+E` 或点击 `Edit: Yes`，会把编辑器切换到查看模式并把更改藏在看不见的地方，十六进制编辑器也是如此，因此之后关闭它可能会丢失这些更改。现在会先询问：保存并查看、丢弃并查看，或继续编辑。
- **打开的文件会跟随其写入权限。** 过去以只读方式打开的文件，在外部操作（`chmod +w` 或版本控制的签出）使其变为可写之后，在编辑器中仍保持只读，直到重新打开它。现在，当文件在磁盘上发生变化时，编辑器会双向跟随其权限，但有未保存的工作时除外；`Ctrl+E` 可以覆盖该模式，直到权限下一次变化。
- **立即退出的外部智能体会说明原因**，并附上它打印的最后一行，而不是显示 "Broken pipe"。
- **在 Linux 上，智能体向管道或设备写入时不再在数据写完之后报错。**
