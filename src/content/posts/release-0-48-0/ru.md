## Добавлено
- **Perforce — встроенный.** В termide есть плагин Perforce: ничего не нужно загружать, он одинаковый на Linux, macOS и Windows, и нужен ему только `p4` в `PATH`. Он выключен, пока его не включат — в Настройки → **Плагины** или как `[plugins.perforce]` с `mode = "on"` в глобальной конфигурации; `mode = "opt-in"` оставляет решение каждому проекту, чей `.termide/config.toml` включает его через `enabled = true`. Строка состояния показывает, в каком состоянии файл в редакторе: `p4: #3/5 (out of date)`, `p4: edit #5/5 · change 1234`, `also opened by …`, `locked by …`, `not in depot`. `Ctrl+E` в файле только для чтения открывает его на правку — сначала спрашивая, если файл уже открыт кем-то другим, и отказывая, если он заблокирован; при выключении в файле, который вы открыли, спрашивает, оставить его открытым или откатить, а при несохранённых изменениях — сохранить их или отбросить. `Alt+G` в проекте вне git перечисляет открытые файлы по changelist'ам в дереве каталогов, с клавишами git status: `Enter` или `F4` открывает файл, `F3` показывает его diff в панели diff, `Backspace` откатывает его, `Space` перечисляет, что с ним можно сделать, а `Enter` на changelist'е отправляет его — changelist по умолчанию через диалог, принимающий описание и список отправляемых файлов. Палитра команд открывает новый файл на добавление, показывает diff файла и выполняет sync рабочего пространства в терминале. Открытые файлы получают свой цвет в файловом менеджере, строки, изменённые относительно депо, отмечаются на полях редактора, как для git, а агент получает инструменты `opened`, `diff` и `edit`. Плагин с тем же именем в каталоге плагинов занимает его место.
- **Плагины могут заменять другую систему контроля версий.** `files/status` раскрашивает файлы в файловом менеджере цветами git, включая каталоги над ними, а `editor/base` даёт текст, относительно которого на полях отмечаются изменения; в обоих случаях git по-прежнему идёт первым, так что плагины дополняют только там, где git сказать нечего. `file/will_edit` сначала передаёт `Ctrl+E` плагину — включение редактирования в файле, доступном на диске только для чтения, или выключение в записываемом, — чтобы плагин мог взять файл на правку или откатить его и сохранить или отбросить несохранённую работу. Команда с `"replaces": "open_git_status"` выполняется по `Alt+G` в проекте вне git. Панель плагина может быть `list` — группы строк с действиями, запускаемыми клавишами git status, строки с путём — в дереве каталогов, кнопки под ними — или `diff`, показанный панелью diff, а `window/dialog` спрашивает в одном окне, собранном из сообщения, текстового поля, списка для выбора или отметки и до шести кнопок.
- **Ключи API в хранилище паролей.** На странице подключения в настройках ИИ есть поле **Ключ API**: введённый там ключ попадает в зашифрованное хранилище под именем подключения и никогда — в `config.toml`, а поле показывает только, сохранён ли ключ. Переменная, названная в `api_key_env`, по-прежнему имеет приоритет. Если ключ лежит в заблокированном хранилище, мастер-пароль спрашивается, когда он нужен запросу. Переименование подключения переносит его ключ, удаление — удаляет ключ. Ключ, по ошибке вставленный в `api_key_env`, показывается маской с предупреждением и переносится в хранилище за один шаг. Запуск из командной строки не может разблокировать хранилище, и ему нужен `api_key_env`.
- **Кто потратил токены сессии.** Сведения о сессии в панели агента (`F3`, `/usage`) раскладывают токены по тому, кто их потратил, — разговор, делегаты, проверяющий `auto`, решатель `recall`, сводки, судья `/goal`, `/handoff` и то, что Claude Code тратит внутри себя, — и по моделям, с долей, выданной из кэша, и, там, где провайдер это сообщает, выводом, потраченным на рассуждения. Ещё они показывают, чем заполнен контекст, — системный промпт, определения инструментов, навыки, вывод инструментов, разговор, сводка и то, что CLI-агент держит у себя, — и во что обошлись результаты каждого инструмента, пока оставались в нём. Цифры берутся из журнала сессии, так что повторно открытая сессия их показывает, итоги в строке состояния продолжают то, что сессия уже потратила, а ответвление считает только своё.

## Изменено
- **Проверяющий Claude Code и Codex работает на самой дешёвой модели.** Если проверяющий не назначен, проверяющий режима `auto` в сессии Claude Code или Codex работал на модели самой сессии, обычно передовой, — около трети расходов на Claude Code, которые шли через termide. Теперь он работает на самой дешёвой модели, которую предлагает CLI, — Haiku для Claude Code, — или на модели сессии, если CLI её не предлагает; проверяющий, назначенный в `[ai.auto_reviewer]` или в подключении, по-прежнему имеет приоритет. Его вызовы также используют пятиминутный кэш Claude Code, а не вдвое более дорогой часовой.

## Исправлено
- **Повторно открытая сессия агента показывает весь разговор и заполненность контекста.** При повторном открытии сессии или перезапуске termide показывалось только то, что оставило последнее сжатие, — сводка под видом вашего первого сообщения, — а контекст показывался как 0 до следующего ответа. Теперь панель показывает каждый блок, с уведомлением о сжатии там, где оно произошло, и заполненность контекста такой, какой она была.
- **Токены проверяющего Claude Code или Codex учитываются.** Проверяющий режима `auto`, решатель `recall` и судья `/goal`, работавшие на Claude Code или Codex, сообщали, что ничего не потрачено, и итоги сессии их не включали.
- **Выход из режима правки спрашивает о несохранённых изменениях.** `Ctrl+E` или щелчок по `Edit: Yes` при несохранённых изменениях переключали редактор в просмотр, пряча их из виду, — и в hex-редакторе тоже, — так что при последующем закрытии они могли потеряться. Теперь он спрашивает: сохранить и перейти к просмотру, отбросить и перейти к просмотру или продолжить правку.
- **Открытый файл следует своим правам на запись.** Файл, открытый только для чтения, оставался в редакторе только для чтения после того, как что-то извне делало его записываемым — `chmod +w` или взятие на правку в системе контроля версий, — до повторного открытия. Теперь редактор следует правам, когда файл меняется на диске, в обе стороны, кроме случая с несохранённой работой; `Ctrl+E` переопределяет их до следующего изменения.
- **Внешний агент, который сразу завершается, сообщает почему** — последней строкой, которую он напечатал, — вместо «Broken pipe».
- **Запись агента в канал или устройство больше не завершается ошибкой на Linux** после того, как данные уже прошли.
