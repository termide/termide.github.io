## Добавлено
- **Perforce — встроенный.** В termide теперь есть плагин Perforce: без Python и без загрузки, одинаковый на Linux, macOS и Windows; нужен только `p4` в `PATH`. Он спит, пока глобальная конфигурация не задаст ему режим (`[plugins.perforce]` с `mode = "on"` или `"opt-in"` и `enabled = true` в файле проекта), так что сам по себе репозиторий его не будит, и работает отдельным процессом, который запускается только в проекте, где он нужен. Он показывает в строке состояния, в каком состоянии файл в редакторе (`p4: #3/5 (out of date)`, `edit · change 1234`, `locked by …`); открывает его на правку, когда `Ctrl+E` включает редактирование в файле только для чтения, — а если файл уже открыт кем-то другим, сначала спрашивает (на добавление — из палитры); предлагает откатить его, когда `Ctrl+E` выключает редактирование, и тогда же спрашивает, сохранить или отбросить несохранённые изменения; по `Alt+G` в проекте вне git перечисляет открытые файлы по changelist'ам в дереве каталогов, где `Enter` открывает файл, `F3` показывает его diff в панели git diff, `Backspace` откатывает его, `Space` перечисляет, что с ним можно сделать, а `Enter` на changelist'е отправляет его — changelist по умолчанию через диалог с описанием и списком отправляемых файлов; показывает diff файла из палитры, выполняет sync в терминале и даёт агенту инструменты `opened`, `diff` и `edit`. Он раскрашивает открытые файлы в файловом менеджере и отмечает на полях редактора строки, изменённые относительно депо, как termide делает это для git. Плагин с тем же именем в каталоге плагинов занимает его место.
- **Плагины могут показывать состояние другой системы контроля версий.** `files/status` раскрашивает файлы в файловом менеджере цветами git (`modified`, `added`, `deleted`, `ignored`), включая каталоги над изменённым файлом, а `editor/base` даёт текст, относительно которого редактор отмечает изменённые строки. `file/will_edit` сначала передаёт плагинам `Ctrl+E` на файле, доступном на диске только для чтения, и обратное выключение на сохранённом файле с правом записи, чтобы плагин мог взять файл на правку или откатить его и сохранить или отбросить несохранённую работу, а не редактор обходил права. Команда с `"replaces": "open_git_status"` выполняется по `Alt+G` в проекте вне git. В обоих случаях git идёт первым: плагины дополняют только там, где git сказать нечего, например вне репозитория. Панель плагина может быть не Markdown, а `list`: группы строк с действиями для каждой, по которым перемещаются и которые запускают клавишами git status, строки с путём — в дереве каталогов, и кнопки под ними; или `diff` — унифицированный diff, показанный так же, как панель git diff показывает diff git. `window/dialog` спрашивает в одном окне, собранном из сообщения, однострочного или многострочного текстового поля, списка для чтения, выбора или отметки и до шести кнопок.
- **Ключи API в хранилище паролей.** На странице подключения в настройках ИИ появилось поле **Ключ API**: введённый там ключ, скрытый маской, попадает в зашифрованное хранилище под именем подключения и никогда — в `config.toml`, а поле показывает только, сохранён ли ключ. Переменная, названная в `api_key_env`, по-прежнему имеет приоритет. Запрос, ключ которого лежит в заблокированном хранилище, спрашивает мастер-пароль; если отменить, он завершается ошибкой с объяснением. Переименование подключения переносит его ключ, удаление — удаляет ключ. Ключ, вставленный в `api_key_env` вместо имени переменной, показывается как `********` с предупреждением, и одним выбором в поле **Ключ API** его можно перенести в хранилище. Запуск из командной строки не может разблокировать хранилище, и ему нужен `api_key_env`.
- **Кто потратил токены сессии.** Сведения о сессии в панели агента (`F3`, `/usage`) раскладывают токены сессии по тому, кто их потратил, — разговор, делегаты, проверяющий `auto`, решатель `recall`, сводки, судья `/goal`, `/handoff`, а также то, что Claude Code тратит внутри себя на собственных делегатов, сводки и вспомогательные вызовы, — и по моделям (токены делегата читаются из его собственного журнала сессии, вместе с его проверяющим); у каждой строки — полоса и доля токенов, где любой вид считается за один, а также доля токенов промпта, выданная из кэша, и там, где провайдер считает это отдельно (Codex, OpenAI-совместимые серверы), — вывод, потраченный на рассуждения. Ещё они показывают, из чего состоит контекст, — системный промпт, определения инструментов, навыки, вывод инструментов, разговор, сводка и то, что CLI-агент держит у себя сверх этого, — и результаты каждого инструмента за сессию (навыка — по имени): что они принесли в контекст и сколько из этого модель перечитывает в последующих вызовах. Цифры берутся из журнала сессии, так что повторно открытая сессия их показывает, а итоги в строке состояния начинаются с того, что сессия уже потратила, а не с нуля; ответвление считает от собственного начала.

## Исправлено
- **Повторно открытая сессия агента показывает заполненность контекста.** При повторном открытии сессии или перезапуске termide её контекст показывался как 0 до следующего ответа, сколько бы в нём ни было с последней сводки; теперь заполненность и размер окна сессии Claude Code или Codex хранятся в её журнале, а у встроенного агента читаются из последнего вызова.
- **Повторно открытая сессия агента показывает весь разговор.** При повторном открытии сессии или перезапуске termide показывалось только то, что оставило в контексте последнее сжатие, — сводка под видом вашего первого сообщения и несколько сохранённых сообщений, — хотя живая панель показывала всё, а журнал хранил всё целиком. Теперь панель показывает каждый блок ветки, с уведомлением о сжатии там, где оно произошло, — так, как это выглядело во время работы; контекст модели не меняется.
- **Токены проверяющего Claude Code или Codex учитываются.** Проверяющий режима `auto`, решатель `recall` и судья цели, если их спрашивали у Claude Code или Codex, сообщали, что ничего не потрачено, и итоги сессии их не включали — около трети расходов на Claude Code, которые шли через termide. Теперь они учитываются и записываются на модель, на которой шёл вызов, включая вызовы, которые агент остановил или отклонил.
- **Выход из режима правки спрашивает о несохранённых изменениях.** `Ctrl+E` или щелчок по `Edit: Yes` в текстовом редакторе с несохранёнными изменениями переключали в просмотр, оставляя их в буфере, а в hex-редакторе правки оставались незаписанными и невидимыми, так что при последующем закрытии они могли молча потеряться. Теперь оба сначала спрашивают: сохранить и перейти к просмотру, отбросить изменения и перейти к просмотру или отменить и продолжить правку.
- **Открытый файл следует своим правам на запись.** Файл, открытый без права записи, оставался в редакторе только для чтения после того, как `p4 edit` или `chmod +w` делали его записываемым, — до `Ctrl+E` или повторного открытия; это первое, на что натыкается пользователь Perforce, ведь Perforce держит файлы только для чтения, пока их не возьмут на правку. Теперь редактор заново смотрит на права, когда файл меняется на диске и когда показывается свёрнутая панель: записываемый файл становится редактируемым, снова только для чтения (`p4 revert`) — только для чтения, если нет несохранённой работы. `Ctrl+E` по-прежнему переопределяет режим до следующего изменения прав, а файл, открытый только для просмотра, остаётся только для чтения.
- **Пример с `p4 edit` в документации по пользовательским командам** назначал `Alt+E`, который открывает новый редактор, так что с клавиатуры его команда никогда не выполнялась; теперь он назначает `Shift+F5`.
