## 新增
- **在每个文本框中，双击选中一个单词，三击选中一行。** 与编辑器中一样，在对话框的输入框、查找栏、代理的输入框、对代理提问的回答、提交信息或设置的输入框中快速按第二下，会选中指针下的单词——任何文字的字母和数字以及 `_`——按第三下则选中该行，单行输入框则全选；随后的拖动按字符扩展选区。此前在设置中双击会选中整个输入框。
- **`read` 能给代理看图片。** PNG、JPEG、GIF 或 WebP 文件会以图片本身返回，并缩小到 1568 px，而不再作为二进制文件被拒绝，因此代理可以查看自己截的屏幕截图或渲染出的页面、图表，并加以修正。Anthropic 模型在工具结果中收到图片，OpenAI 兼容模型在工具结果之后的一条用户消息中收到，调用 termide 的 `read` 的外部代理则以 MCP 图片的形式收到。
- **只属于用户的技能。** 前置元数据中带有 `disable-model-invocation: true` 的技能不会进入系统提示词、`skill` 工具和工具集计数；它仍然可以作为 `/name` 发送，`/` 列表和 AI → 技能 会将其标为 *(仅手动)*。为 Claude Code 编写的技能包（例如 mattpocock/skills）由此可以避免其需由用户触发的工作流被模型自行启动。
- **委派的任务在代理面板中运行。** `[ai]`（设置的 AI 选项卡）或受托代理的 `AGENT.md` 中的 `subagent_run` 决定 `task` 在哪里运行：`hidden`，像以前一样在幕后运行（默认）；`existing_panel`，在一个仍显示横幅、没有输入内容且未获得焦点的已打开代理面板中运行，否则在幕后运行；`panel`，在没有空闲面板时，在其他面板旁打开一个新面板运行，且不夺取焦点；`ask`，弹出一张卡片，列出一起交出的任务，并只询问一次它们去哪里。在面板中，你可以看着受托代理工作，并在常规卡片上回应它的权限请求，因此 Claude Code、Codex 和 Gemini CLI 也能担任受托代理。输入框显示 `& Delegate of <agent>: <task>`，不接受输入；`Esc` 停止任务，`Ctrl+T` 经确认后接管任务，关闭面板前会先询问，并说出正在等待它的代理。被占用的面板保留其编号，任务结束后恢复为所在目录中默认代理的新面板。在委派方面板的状态条中单击该任务所在行，会把受托代理的面板调到前面。受托代理面板的 `auto` 审查者依据你向委派方代理提出的要求来判断，而不只是依据任务本身。
- **幕后的受托代理可以向你提问。** 当其上级有可询问的用户时，它会获得 `question`；它的卡片出现在上级的面板中，标题为 `& <delegate> ·`。它的权限请求仍会被拒绝——那些请求应在面板中处理。
- **每个委派任务都保留会话日志。** 无论在幕后还是在面板中、在 termide 的循环上还是在 Claude Code 上，包括被停止的任务：日志写明委派它的会话、代理和 `task` 调用，开头记录它运行时使用的连接、模型和代理，并在会话列表中标记为 `&`。在 `task` 块上按 `o` 即可打开它。
- **不同面板中的代理可以相互交谈。** 内置代理以及使用 termide 工具的 Claude Code 获得 `agents` 和 `send_message`：前者列出项目中的代理面板及其编号、代理、状态和目录，后者向其中之一发送 `info`、`question` 或 `reply`。消息会在空闲面板上开启一轮，或加入正在进行的运行；对话记录在其开头标出发送者，模型和 `auto` 审查者会把它当作另一个代理的话来读，而绝不是你的话。`ask` 模式下每条消息都需确认，计划模式下不发送任何消息；在你一言不发的情况下发出十条消息后，下一条会被拒绝，直到你写点什么。正在运行委派任务的面板不接收消息。
- **代理覆盖其他面板改动的编辑会被拦下。** 不同面板中的代理可能处理同一批文件：如果某个文件在本面板上次读取之后被另一个面板修改过，或者本面板从未读取过它，那么对它的 `edit` 或 `write` 会被拒绝，并告诉代理先重新读取。通过 `bash` 或在 termide 之外所做的修改无法察觉。
- **`on_limit = "ask_else_wait"` 遇到限额时先询问，无人回答则等待限额过去。** 失败卡片与 `ask` 一样弹出；如果到等待本应重试的时刻——错误中给出的重置时间或退避间隔——仍无人回答，请求就会自行再次发送，因此无人值守的 `/goal` 或 `/loop` 不会停在卡片上。卡片会对这一时刻倒计时。如果重新打开时卡片恢复显示而重置时间已过，会先留出大约半分钟让你阅读。
- **在后台运行的委派任务。** `task` 接受 `background`：任务交给一个代理面板，调用立即返回，因此委派方代理在受托代理工作时可以继续自己的工作；受托代理的回答稍后作为它的一条消息到达。关闭任务所在的面板即结束任务。要求使用后台代理的技能（例如 mattpocock/skills 中的 `research` 和 `implement-spec`）现在能得到一个。
- **受托代理的输入框可以回到委派方面板。** 当一个面板在运行另一个代理的任务时，单击其显示 `& Delegate of <agent>: <task>` 的输入框，会把委派方代理的面板调到前面，正如在那里单击任务所在行会把受托代理的面板调到前面一样。
- **向本地模型回传推理**（[#62](https://github.com/termide/termide/issues/62)）。OpenAI 兼容连接接受 `send_reasoning`（`auto`、`on`、`off`；其设置页面上的 **回传推理**）：它把模型的推理作为 `reasoning_content` 随其先前的回答一起回传，并在使用 `enable_thinking` 时请求聊天模板启用 `preserve_thinking`——没有它，Qwen 3.6 会丢失先前的思考，回答也会变差。`auto` 在推理级别通过 `enable_thinking` 传递的地方开启它，默认即本地服务器。
- **在代理横幅上搜索会话。** 在新会话的横幅上按 `Ctrl+F`，输入框会变成对其会话列表的搜索，标题为 **搜索会话** 并显示匹配数：列表只保留标题匹配的会话，模糊匹配，最佳的在前，匹配的字母带下划线。方向键直接从查询中遍历匹配项，`Enter` 打开其中之一，`F2` 和 `F8` 重命名或删除它，`Esc` 立即结束搜索，并把你之前输入的内容放回输入框。
- **来自 `~/.agents/skills/` 的技能。** 用户的跨代理技能目录——`npx skills add -g` 以及 Codex、pi 等存放技能的位置——作为最低一级的技能层级读取。
- **必要时不调用模型就把上下文裁剪到合适大小。** 当压缩的摘要被拒绝，或者模型调用工具而不是进行总结时，上下文会按照丢失代价从低到高裁剪到窗口的一半——先是推理，然后是只读输出、长输出和参数，再是旧的探索过程（只保留其中的决定）和最早的消息——同时保留最近几轮、你的请求以及每个调用及其结果。用于总结的那次调用自身的输入也以同样方式裁剪到窗口大小，因此不会再因超出窗口而运行半个小时。接管对话的外部代理会在其窗口一半的范围内得知整段对话，而不再是一份上限为 100 K 字符的决定回顾。

## 变更
- **在计划模式下，MCP 工具经你同意即可使用。** 计划模式不再拒绝所有 MCP 工具：其服务器标为只读（`readOnlyHint`）的工具直接运行，已配置的规则或你在本会话中的回答所允许的工具也会运行，其余的则会询问，并提供“始终允许”选项——这样代理在制定计划时就可以从任务跟踪器的 MCP 服务器读取工单。`deny` 规则以及在工具菜单中关闭的工具仍然会把工具挡在外面。
- **在 `edit` 模式下，其服务器标为只读的 MCP 工具无需询问即可运行**，与该模式下的网络工具一样。
- **状态条的每一行外观统一。** 等待中的重试、请求的暂停、排队的消息、`/goal`、`/loop`、子代理和后台命令现在以同样的方式显示：符号和它是什么用强调色，相关信息和它处理的对象用暗色，右侧边缘是已持续时间，可取消的还带有 `✕`。循环在左侧显示已运行时长、周期、次数和下次运行时间；排队的消息和待定的暂停显示已等待的时间。所有行都不再旋转——由对话记录中的实时行来旋转——等待中的重试多了一个可放弃它的 `✕`。
- **`Esc` 先清空已输入的提示，再停止运行。** 代理工作时，第一次按 `Esc` 清空输入框；再按一次停止运行，同时停止进行中的 `/goal` 或 `/loop`。
- **失败卡片说明接下来会发生什么，并与时钟保持一致。** 其详情先说明即将发生的事——重置、退避、已在进行的等待——而不是重复上方已显示的错误；卡片打开期间倒计时会走动；重置时间一过，相应行即消失，只留下 **立即重试**。切换到另一个代理的那一行已移除：限额属于连接，而连接可从状态栏切换，卡片在切换期间保持显示。
- **外部代理的状态栏不再显示 `(acp)`**；旁边的连接标签会写明程序名称。

## 修复
- **单击输入框的边框也会放置光标。** 在书签、命令、命令参数、另存为、输入、按模式重命名和可编辑下拉选择对话框中，在输入框方框内的任意位置按下，都会像按在文本上一样使其获得焦点并把光标放进去：在上方或下方边框上放到所指的列，在左边框上放到可见内容的开头，在右边框上放到其末尾。此前它只会让输入框获得焦点，在某些对话框中甚至毫无反应。组合框的箭头仍然会打开其列表。
- **拖过提交信息的边缘会使其滚动。** 拖到可见行的上方或下方时，指针每移动一次，信息就滚动一行，选区也随之延伸到新出现的行上，与编辑器中一样；此前它会停在显示的第一行或最后一行。
- **在每个对话框的输入框中，单击放置光标，拖动进行选择。** 在按模式重命名对话框，复制、移动、打包和解包的目标对话框，书签、命令和命令参数对话框，以及目录选择器的新建文件夹和重命名输入框中，按下会把光标放在指针下的字符上并使输入框获得焦点，从那里拖动则进行选择，越过输入框两侧时到达文本的开头或末尾；提交信息也可以通过拖动来选择。二进制查看器的查找栏接受单击和拖动；在终端查找栏中开始的拖动，在指针离开查找栏时仍在那里继续选择，而不会在终端中开始新的选择。命令参数对话框的文本框重新绘制在自己的行上，而不是覆盖在下一个标签上。
- **粘贴到单行输入框时，单词之间保持分隔。** 粘贴文本中的换行会变成空格，而不是把各行粘连在一起；复制的行末尾的换行会被丢弃，而不是留下一个尾随空格。
- **设置中的 LSP 服务器表单按键盘实际发送的内容输入。** 它的输入框会把按键转换为拉丁布局，因此西里尔字母变成了拉丁字母，`+` 和 `_` 变成了 `=` 和 `-`；现在它们与其他设置输入框一样按实际输入接收按键，`Ctrl` 快捷键在任何布局下仍然有效。
- **终端的粘贴进入打开的对话框，绝不会进入下方的面板。** 按模式重命名对话框以及复制、移动、打包和解包的目标对话框会像接收键入一样把括号粘贴接收到其输入框中；此前粘贴会进入下面的面板——进入正在编辑的文件或 shell。没有输入框的对话框现在也会阻止粘贴进入面板。
- **复制、剪切和粘贴在查找栏中可用。** 当编辑器、终端、文件管理器、二进制查看器、日志、Markdown 或 HTML 的查找栏获得焦点时，`Ctrl+C`/`X`/`V` 以及终端的粘贴作用于其输入框并重新搜索；此前粘贴会进入正在编辑的文件、进入 shell 或者丢失，而在文件管理器中这些键会复制文件。
- **`Ctrl+Y` 在文本框中重做，与编辑器中一样。** 在输入框、筛选框和代理的输入框中，它违反文档中的按键说明执行了撤销；在终端发送大写字母的地方，`Ctrl+Shift+Z` 现在也可以重做。
- **为委派任务打开的面板在任务结束时关闭。** 此前它会被重新设置为空的代理面板并保持打开；为任务占用的空闲面板仍然会在其原来工作的位置恢复为默认代理。
- **筛选框和小型编辑器的编辑方式与其他输入框一致。** 命令面板和项目切换窗口的筛选框、Git 状态中的仓库和分支筛选框、数据库筛选值、行编辑器的字段、表格的单元格编辑器以及提交信息现在共用应用的编辑按键：光标以反色单元格显示在其所在位置，文本在那里输入，而不只是在末尾；`Shift`/`Ctrl` 加方向键进行选择和按单词跳转，`Ctrl+A`、撤销和重做可用，`Ctrl+C`/`X`/`V` 执行复制、剪切和粘贴，而不是在筛选框中输入 `v`。粘贴的内容会落在输入框中。在命令面板和项目切换窗口中，`Home`/`End` 现在在筛选框中移动，`Ctrl+Home`/`Ctrl+End` 跳到第一项和最后一项；在打开的单元格编辑器中，复制、剪切和粘贴命令作用于单元格的文本，而不是表格。
- **对代理提问的键入回答与任何输入框一样编辑。** 光标无论在哪里都以反色单元格显示，输入时空格不再被吞掉，`Shift`/`Ctrl` 加方向键、`Ctrl+A` 和撤销可用，单击放置光标，拖动进行选择，粘贴、复制或剪切作用于回答，而不是下方的输入框；粘贴的换行会变成空格。
- **`Ctrl+K` 显示悬停文档**（[#63](https://github.com/termide/termide/issues/63)）。通过键盘请求的弹窗只绘制在鼠标指针处，因此当鼠标不在编辑器上时，服务器的回答（包括 gopls 的 godoc）从未出现。现在它在文本光标处打开；由鼠标触发的悬停仍在指针处打开。
- **`suggest_command` 在计划模式下可用。** 它的卡片按文档所述只带有“复制”和“不运行”；此前计划模式会拒绝该调用，卡片也不会出现。
- **在后台打开的项目中，受托代理能得到自己的面板。** 不在屏幕上的项目中的代理无法访问其项目的面板：本应在面板中运行的任务在幕后运行，作为受托代理的外部代理和后台任务会失败，`agents` 和 `send_message` 也被拒绝。现在任务会在该项目中占用一个面板，切换到该项目时即可看到，消息和后台回答也能到达其面板。
- **被 Claude Code 移到后台的命令仍然可见。** 为了接收在 termide 工具运行长命令时输入的消息，Claude Code 会把该命令移到后台并作出回答；此时运行会结束，而命令仍在继续，却没有任何显示。现在只要 termide 仍在为代理运行某个调用，代理自己的运行就会继续：时钟一直走到命令结束且代理处理了它为止，状态条为该命令固定一行（`$ Running cargo test …`，带有自己的时钟；单击会把其块滚动到视野中），`Esc` 也会停止该命令。
- **在 Claude Code、Codex 和 Gemini CLI 上，`recall` 会排除调用它的会话。** 面板的会话日志没有传给外部代理对 termide 工具的调用，因此它自己的问题以及之后的步骤会作为最前面的结果返回；现在与内置代理一样，只搜索被压缩从上下文中移除的内容。
- **`recall` 的结果噪声更少。** 不再搜索它自己先前的调用和结果（它们重复旧问题和其他条目的片段，被删除的会话也会在其中残留），工具调用——顺带提到某个主题的编辑内容或脚本正文——的权重是回答的一半，此前为 0.8。
- **限额的询问在关闭 termide、切换连接和睡眠后仍然保留。** 在失败卡片显示时或在等待限额期间关闭的会话，现在重新打开时会回到同一张卡片，在列表中标记为 ⏸，其 `/goal` 或 `/loop` 也在等待它，在得到回答之前不运行任何东西。从状态栏切换连接——绕过订阅限额的办法——不再会丢掉卡片、让请求既不重试也不放弃；请求已经成功的会话也不会再被问及此事。在机器睡眠期间到达的重置时间会在唤醒时立即重试，而不是几个小时之后。上次运行中其代理持有此类请求的项目会在启动时于后台加载，因此不进入该项目，其等待或卡片也会按时进行。
- **在外部代理的调用中被中断的运行会提供继续选项。** 在 Claude Code 运行长命令时关闭 termide，会话看起来像已完成，重新打开的面板也不询问任何事情；现在被中断的调用会出现在对话记录中，并附有说明这一点的结果，继续卡片也会弹出并响铃。
- **重新打开的会话保留其权限模式。** 在计划模式下暂停的运行会在配置的模式下继续，没有计划提示和防护；现在模式会被记录并恢复，撤销或回退也会保持你当前所在的模式。
- **在重新打开的外部代理上继续 `/goal` 不再会丢掉它。** 它的检查发生在代理仍在启动时，拒绝便结束了目标；现在会在一秒后再次询问，已停止的代理算作检查失败，会重试，随后暂停并保留目标。
- **Claude Code 工作时输入的消息会及时显示。** 代理一接收它，它就从队列条中消失，直到对它的回答之后才出现在对话记录中，看起来像被忽略了；现在它会留在状态条中直到被记录，并在其回答之前被记录。
- **外部代理的用量不再被当作上下文大小。** Claude Code 报告的是整轮的消耗（包括缓存读取），这会填满上下文条，并在回到内置代理时立即触发压缩。
- **鼠标滚轮滚动视图**，适用于设置（包括 快捷键 选项卡）以及诊断、大纲和 Git 日志面板，每格三行。此前它移动的是一个隐藏的选择项，视图只有在其到达边缘时才跟随，因此最初几格看起来像丢失了。
- **下拉选择器在其面板失去焦点时关闭**——Git 状态和 Git 日志中的仓库和分支选择器，以及数据库查看器中的数据库和表选择器。
- **零散的系统消息不再覆盖在屏幕上。** 其他代码写入 stderr 的输出——在 macOS 上，粘贴用 `Ctrl+X` 剪切的文件后出现的 `sandbox_extension_consume failed`——会横穿各个面板；现在它会进入日志。

## 安全
- 将 `rustls` 更新至 0.23.46，修复 RUSTSEC-2026-0346 至 0349；将 `ruzstd` 更新至 0.9.1，修复 RUSTSEC-2026-0344。`rustls` 承载 termide 的 TLS——模型提供方、`fetch`、远程 MCP 服务器、数据库和 FTPS 连接——`ruzstd` 负责打包和解包 zstd 归档。
