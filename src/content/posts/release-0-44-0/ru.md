## Добавлено
- **Настройки отладчиков.** `[debug]` в `config.toml` задаёт, как запускается каждый отладчик, глобально или для одного проекта: `[debug.debuggers.<name>]` указывает его программу (`command` — `lldb-dap` собственной сборки LLVM, `dlv` вне `PATH`, Python, который нужен debugpy) и флаги, которые он получает при каждом запуске (`args` — вместо его флагов по умолчанию, перед собственными `debugger_args` запуска); `native` задаёт порядок отладчиков, которые пробует файл Rust без команды, а `console` — где адаптер по умолчанию запускает программу. `--only-same-user=false` для Delve в Termux теперь стал там `args` по умолчанию для `dlv-dap` — он виден и заменяем, а не зашит в код. В окне настроек для всего этого есть вкладка **Отладка** со страницей на каждый отладчик.
- **Собственные флаги отладчика.** `debugger_args = ["--log", "--log-output=dap"]` в отладочной команде `commands.toml` добавляет флаги самому отладчику — туда, где он читает свои параметры: после собственных аргументов адаптера, перед `--`/`--args` для lldb и gdb, перед подкомандой для Delve, перед `-c` у pdb. В форме **Настройка отладки** для них есть поле. До сих пор единственным способом был скрипт-обёртка под именем отладчика.
- **Rust отлаживается без команды.** `F5` на файле Rust в проекте Cargo предлагает его исполняемые файлы, найденные через `cargo metadata`: тот, чей это главный файл, иначе исполняемые файлы его пакета, иначе все исполняемые файлы рабочего пространства. Каждый сначала собирается командой `cargo build -p <package> --bin <name>` и запускается из корня рабочего пространства под `lldb-dap`, адаптером GDB или `lldb` в терминале — смотря что установлено. Если ничего из этого нет, или для файла Go нет Delve, окно сообщает, что установить, — раньше для Go запускался отсутствующий `dlv`. Инструмент агента `debug` запускает файлы Rust так же.
- **Настроить отладку…** в меню `[≡]` редактора и в палитре команд открывает форму для запуска: его имя, программа и её аргументы, сборка, которая выполняется сначала, и отладчик — всё заполнено для файла в редакторе. **Запуск** сохраняет его как отладочную команду в `.termide/commands.toml` проекта и запускает. `F5` открывает ту же форму, когда запускать нечего, — раньше он не делал ничего заметного.

## Изменено
- **Сообщения между агентами читаются как шаги, все под `&`.** Сообщение другого агента — ответ, вопрос или заметка панели, ответ фоновой задачи, задача, переданная панели делегата, — показывалось на плашке собственных сообщений пользователя с заголовком `› & default · reply` и читалось как слова пользователя или окончательный ответ. Теперь это шаг, как вызов инструмента, с текстом, свёрнутым под ним: `& Receiving reply from default (panel 3) · …`, `& Receiving question from …`, `& Receiving note from …`, `& Taking task from …`. Отправленное сообщение тоже читается по своему виду — `& Asking panel 3 · …`, `& Replying to panel 1 · …`, `& Telling panel 3 · …`, а `agents` — это `& Listing agent panels`: `&`, значок задачи, теперь открывает любой обмен с другим агентом, тогда как у `send_message` и `agents` был `@` — значок блока рассуждений.

## Исправлено
- **Файлы библиотек открываются в языковом сервере проекта.** Файл стандартной библиотеки, где останавливается отладчик, или зависимости в `~/.cargo/registry`, куда ведёт переход к определению, получал собственный rust-analyzer: для стандартной библиотеки тот падал на nightly-манифестах, собирал build-скрипты внутри инструментария и запускал там `cargo check`, не останавливая спиннер и нагружая процессор. Такие файлы — `rustlib/src` для Rust, `~/.cargo/registry` и `~/.cargo/git`, `GOROOT` и `pkg/mod` для Go — теперь открываются в сервере проекта, последним открытого для этого языка, где они уже загружены.
- **Отладочная сборка больше не ждёт rust-analyzer.** rust-analyzer проверял и собирал свои build-скрипты в `target/` проекта, удерживая блокировку, которая нужна `cargo build` для отладчика; теперь он получает `target/rust-analyzer` (`cargo.targetDir = true`). Взамен его артефакты собираются дважды, один раз после обновления.
- **Go отлаживается в Termux.** Delve принимает локальное подключение только от пользователя, который его запустил, а в Linux проверяет это, читая `/proc/net/tcp`, доступ к которому Android 10 и новее запрещает приложениям; тогда он закрывал подключение termide с «closing connection from different user», и сессия завершалась (go-delve/delve#3202). Там, где этот файл прочитать нельзя, termide теперь запускает `dlv dap` с `--only-same-user=false`, так что скрипт-обёртка, добавлявший этот флаг, больше не нужен; в остальных местах проверка остаётся включённой.
- **Сообщения о состоянии попадают в журнал.** То, что termide сообщал в строке состояния, — неудачное переключение предпросмотра, снятые точки останова, уведомление панели — хранилось для статусной строки, которая его больше не рисует, так что никто этого не видел; теперь оно пишется и в журнал, ошибки — как предупреждения.
- **Отладочная сессия, которая не смогла запуститься, говорит почему.** Адаптер, завершившийся до запуска, оставлял в панели только «the debug adapter exited», а в журнале — ничего, даже если он разорвал связь с termide, продолжая работать. Теперь сообщение о сбое говорит, завершился ли адаптер, и с каким статусом, или только закрыл подключение, и заканчивается последней напечатанной им строкой: для Delve в Termux, чья проверка того же пользователя не может прочитать `/proc/net/tcp` на Android, это `closing connection from different user`. То, что адаптер печатает до запуска программы, пишется в журнал на уровне `info`, и termide дожидается его последних строк, прежде чем сообщить о сбое. Неудачная сборка так же называет свою последнюю строку, а журнал фиксирует, когда сессия завершается, останавливается или программа выходит со своим кодом.
- **Агенты больше не расспрашивают панель, в которой ещё ничего не спрашивали.** Агент, искавший, кто сделал незакоммиченные изменения, спрашивал каждую панель из списка `agents`, в том числе свежую, и та начинала сессию только затем, чтобы ответить, что ничего не знает. Теперь `agents` помечает такую панель `free (nothing asked yet)` и сообщает, что её агент ничего не знает о проделанной работе, а `send_message` отклоняет обращённый к ней `question`; `info` по-прежнему проходит.
- **LSP-сервер открывается на собственной странице, как подключение AI.** **+ Добавить сервер** или сервер на вкладке LSP в настройках открывает свою страницу: язык, команда, аргументы и маркеры корня — обычными полями, сохраняемыми по мере правки, затем **К списку** и **Удалить сервер**; `Esc` или `Backspace` тоже возвращают назад. Форма, которую она заменяет, оставляла под собой строки списка для мыши, так что щелчок по полю мог открыть другой сервер или строку добавления, и показывала строку подсказок по клавишам. Сервер, добавленный и оставленный без команды, при возврате удаляется.
- **Длинные строки в выводе панели отладки переносятся.** Они обрезались по краю панели, что скрывало конец ошибки адаптера — обычно ту часть, где сказано почему.
- **Структура заполняется для восстановленной раскладки.** При запуске, при переключении проекта или при возвращении отложенного проекта структура оставалась пустой, пока редактор не правили, не перефокусировали или не открывали заново: ничто не передавало ей текст восстановленного редактора, а живая синхронизация ждёт правки. Теперь она сразу заполняется из активного редактора, а когда ей приходится выбирать редактор самой, она берёт активный, а не первый в раскладке.
- **Щелчок по списку на баннере агента выбирает сессию, а не открывает её.** Одиночный щелчок по недавней сессии сразу открывал её вместо свежей. Теперь первый щелчок переводит туда курсор списка; щелчок по уже выбранной сессии или двойной щелчок её открывает.
- **Выбор запуска из списка отладки запускает его.** Когда `F5` или **Начать отладку** предлагали несколько вариантов запуска — отладочную команду и файл Python, Go или Rust в редакторе, — выбранный из списка ничего не делал.
