## 新增
- **调试器设置。** `config.toml` 中的 `[debug]` 规定每个调试器如何启动，可全局设置，也可针对单个项目：`[debug.debuggers.<name>]` 给出它的程序（`command`，例如自定义 LLVM 的 `lldb-dap`、不在 `PATH` 中的 `dlv`、debugpy 所需的 Python）以及每次启动都会传给它的参数（`args`，替代其默认参数，位于启动项自己的 `debugger_args` 之前）；`native` 规定没有命令时 Rust 文件依次尝试哪些调试器，`console` 规定适配器默认在哪里运行程序。Termux 中 Delve 的 `--only-same-user=false` 现在是那里 `dlv-dap` 的默认 `args`，可见且可替换，而不是写死在代码中。设置窗口有一个 **调试** 选项卡涵盖这一切，每个调试器一页。
- **调试器自身的参数。** 在 `commands.toml` 的调试命令中写入 `debugger_args = ["--log", "--log-output=dap"]`，会把参数加到调试器本身读取选项的位置：适配器自身参数之后，lldb 和 gdb 的 `--`/`--args` 之前，Delve 的子命令之前，pdb 的 `-c` 之前。**设置调试** 表单中有对应的字段。此前唯一的办法是用调试器的名字写一个包装脚本。
- **Rust 无需命令即可调试。** 在 Cargo 项目中对 Rust 文件按 `F5`，会提供通过 `cargo metadata` 找到的可执行目标：以该文件为主文件的那个，否则是其所在包的可执行目标，再否则是整个工作区的所有可执行目标。每个目标都先用 `cargo build -p <package> --bin <name>` 构建，然后在工作区根目录下用已安装的 `lldb-dap`、GDB 的适配器或终端中的 `lldb` 运行。如果都没有安装，或者 Go 文件缺少 Delve，会弹出窗口说明需要安装什么——过去 Go 会去启动一个并不存在的 `dlv`。代理的 `debug` 工具以同样方式启动 Rust 文件。
- 编辑器的 `[≡]` 菜单和命令面板中的 **设置调试…** 会打开一个启动项表单：名称、程序及其参数、先运行的构建以及调试器，均按编辑器中的文件预先填好。**运行** 会把它作为调试命令保存到项目的 `.termide/commands.toml` 中并启动。没有可启动的内容时，`F5` 会打开同一个表单，过去它看起来什么也不做。

## 变更
- **代理之间的消息显示为步骤，全部位于 `&` 下。** 另一个代理的消息——某个面板的回复、问题或通知，后台任务的回答，交给受托代理面板的任务——过去显示在用户自己消息的底板上，标题为 `› & default · reply`，读起来像用户的话或最终回答。现在它与工具调用一样是一个步骤，文本折叠在其下：`& Receiving reply from default (panel 3) · …`、`& Receiving question from …`、`& Receiving note from …`、`& Taking task from …`。发出的消息同样按其类型显示：`& Asking panel 3 · …`、`& Replying to panel 1 · …`、`& Telling panel 3 · …`，`agents` 则显示为 `& Listing agent panels`：`&` 是任务的符号，现在用于开启与另一个代理的每次交流，而此前 `send_message` 和 `agents` 使用的是推理块的符号 `@`。

## 修复
- **库文件在项目的语言服务器中打开。** 标准库的文件（调试器停下的地方）或 `~/.cargo/registry` 中依赖的文件（跳转到定义所到之处）过去会各自获得一个 rust-analyzer：对于标准库，它会在 nightly 清单上失败，在工具链内部构建构建脚本并在那里运行 `cargo check`，让旋转指示一直转、CPU 一直忙。现在这类文件——Rust 的 `rustlib/src`、`~/.cargo/registry` 和 `~/.cargo/git`，Go 的 `GOROOT` 和 `pkg/mod`——会在该语言最近打开的项目的服务器中打开，那个服务器已经加载了它们。
- **调试构建不再等待 rust-analyzer。** rust-analyzer 在项目的 `target/` 中检查并构建其构建脚本，占用了为调试器执行 `cargo build` 所需的锁；现在它使用 `target/rust-analyzer`（`cargo.targetDir = true`）。代价是其产物要构建两次，在更新后构建一次。
- **在 Termux 中调试 Go。** Delve 只接受来自启动它的用户的本地连接，在 Linux 上它通过读取 `/proc/net/tcp` 来检查这一点，而 Android 10 及更高版本禁止应用读取该文件；于是它以 "closing connection from different user" 关闭 termide 的连接，会话随之结束（go-delve/delve#3202）。现在在无法读取该文件的地方，termide 以 `--only-same-user=false` 启动 `dlv dap`，因此不再需要添加该参数的包装脚本；在其他地方，该检查仍然开启。
- **状态消息会进入日志。** termide 在状态行中报告的内容——预览切换失败、断点已清除、面板的通知——原本留给一个已不再绘制它的状态栏，因此没有人看到；现在它们也会写入日志，错误记为警告。
- **启动失败的调试会话会说明原因。** 在启动之前退出的适配器只在面板中留下 "the debug adapter exited"，日志中什么也没有，即使它其实是在仍在运行时挂断了与 termide 的连接。现在失败信息会说明适配器是退出了（以及退出状态）还是只是关闭了连接，并以它打印的最后一行结尾：对于 Termux 中的 Delve——其同用户检查在 Android 上无法读取 `/proc/net/tcp`——那一行是 `closing connection from different user`。适配器在程序启动之前打印的内容以 `info` 级别写入日志，termide 会等它的最后几行输出完再报告失败。构建失败时同样会写出其最后一行，日志还会记录会话何时结束、停止，或程序以何种退出码退出。
- **代理不再向尚未被问过任何事的面板提问。** 寻找未提交改动作者的代理会询问 `agents` 列出的每个面板，包括新面板，结果在那里开启一个会话，只为回答它一无所知。现在 `agents` 把这样的面板标为 `free (nothing asked yet)`，并说明其代理对目前的工作一无所知，`send_message` 也会拒绝向它发送 `question`；`info` 仍可发送。
- **LSP 服务器在自己的页面中打开，与 AI 连接一样。** 在设置的 LSP 选项卡中，**+ 添加服务器** 或某个服务器会打开它的页面：语言、命令、参数和根标记作为普通字段，编辑即保存，下面是 **返回列表** 和 **删除服务器**；`Esc` 或 `Backspace` 也会返回。它所取代的表单下方仍保留着列表的行供鼠标使用，因此单击某个字段可能会打开另一个服务器或添加行，并且它还显示一行按键提示。添加后未填写命令就离开的服务器会在返回时被丢弃。
- **调试面板输出中的长行会换行。** 它们过去在面板边缘被截断，从而隐藏了适配器错误的结尾，而那通常正是说明原因的部分。
- **大纲会为恢复的布局填充内容。** 在启动时、切换项目时或后台项目回来时，大纲一直为空，直到编辑器被编辑、重新获得焦点或重新打开：没有任何东西把恢复的编辑器文本传给它，而实时同步要等到编辑才发生。现在它会立即从活动编辑器填充；当它需要自己选择编辑器时，会选择活动编辑器，而不是布局中的第一个。
- **单击代理横幅列表中的会话会选中它，而不是打开它。** 单击一个最近的会话会立即打开它，取代新会话。现在第一次单击把列表的光标移到那里；单击已选中的会话或双击才会打开它。
- **从调试列表中选择启动项会启动它。** 当 `F5` 或 **开始调试** 提供多个启动项——一个调试命令以及编辑器中的 Python、Go 或 Rust 文件——时，从列表中选择的那一项什么也不做。
