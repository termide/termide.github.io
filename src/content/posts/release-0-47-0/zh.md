## 新增
- **智能体可以停止它自己启动的工作。** 交给后台的任务即使智能体已不再需要——计划变了，或另一个来源已经给出了答案——也会一直运行到结束；Claude Code 为了接收你的消息而移到后台的委托或命令也是如此：只有你能通过它那一行的 `✕` 停止它们，而智能体被要求停止时，只能说自己无能为力。新的 `jobs` 工具列出智能体启动且仍在运行的工作——后台任务、因限额而暂停的任务、移到后台的调用——每项附有 id、内容和已运行的时长；`stop` 可以停止其中一项而无需询问你，因为那是智能体自己的工作；之后它不会再有回复，智能体也就不会被无故唤醒。这些步骤显示为 `& 列出后台工作` 和 `& 停止 <id>`。`/goal` 或 `/loop` 仍归你掌控。`jobs` 随 `task` 一同提供。
- **比智能体面板更宽的图表可以横向平移。** 回答中比面板更宽的 ```` ```mermaid ```` 图表过去会在右边缘被截断，无法看到其余部分。现在它的各行保持完整，下方有一条滚动条；在图表上使用水平滚轮或 `Shift`+滚轮、点击或拖动其滚动条，或在聊天中选中其所在回答时按 `Shift+→`/`Shift+←`，都能平移它，而 `┊` 竖条保持不动。能放下的图表外观与以前相同。
- **写给正在等待委托的智能体的消息会立即送达。** 面板的智能体等待 `task` 调用时输入的消息，过去会一直排在队列中，直到委托完成，无论这要多久，因此告诉智能体该任务已无关紧要时为时已晚。现在任务会移到后台：调用随即返回任务的 id，任务在输入框上方获得自己的一行，其回答稍后以消息形式送达，于是智能体能马上读到你的消息，并可以用 `jobs` 停止该任务。当智能体之间无需你参与而互传的消息超过上限时，该任务仍会被等待。
- **从目录树中选取目标路径。** 复制、移动、打包、解包和另存为都在同一个路径字段中询问目标位置，其下拉列表是一棵目录树：`Tab`、点击或箭头打开它，`↓` 进入它，`Enter` 保留路径，`Esc` 将其还原。未改动的字段先列出各面板的目录，然后是该项目中最近确认过的目标（`最近`，保留到 termide 退出，从不写入磁盘），再是驱动器或挂载点（`磁盘`）；已编辑的字段列出其文本所指的目录，并按末尾部分进行模糊过滤。在树中移动会把路径写入字段，并保留单个文件的文件名；树可以用文件管理器的按键新建、重命名和删除空目录，以及显示隐藏目录。打包时可在一行中选择归档格式，该行会随之替换扩展名。
- **智能体记录中的图片。** `read` 返回的图片显示在其调用下方，即使已折叠也是如此；你粘贴的图片显示在你的消息内。图片使用终端的图形功能绘制（Kitty、Sixel、iTerm2 或半块字符），居中显示，大小不超过面板高度或宽度一半中较大的那个。只有当图片完全位于屏幕上时才会绘制，在 Sixel 和 iTerm2 上则只在它停止移动后绘制，因此滚动依然流畅。外部智能体的视图同样会显示 termide 工具返回的图片。
- **长图表和写出的页面折叠为卡片。** 高度超过智能体面板一半的 Mermaid 图表显示为一行卡片，直到手动展开其所在回答。对 HTML、Markdown 或 Mermaid 文件的 `write` 会在其标题下添加一张卡片：点击或按 `o` 在其查看器中打开该文件，`Alt`+点击则在 termide 之外打开。
- **智能体可以调试带参数的命令，并且单步执行无需询问。** `debug` `start` 过去拒绝任何带有 `params` 的命令；现在它按名称接收值，其余参数保留默认值，且每个值都必须符合其字段。在计划模式之外，单步、暂停、停止、断点和栈帧都不再询问任何人，因为启动已经决定过了；`start` 和 `evaluate` 仍受规则约束，而规则现在看到的是实际运行的内容（`start debug-server`、`evaluate <expr>`），而不是单纯的动作。`debug` 调用的标题是其本地化的动作——`→ 正在调试 debug-server`、`● 正在设置断点 src/main.rs:42`——而不是原始 JSON。
- **SFTP 校验服务器密钥并遵循 ssh_config。** 过去任何服务器密钥都会被接受，因此网络路径上的任何人都可以冒充服务器并获取密码。现在会在发送任何内容之前，根据 `known_hosts` 校验密钥；未知主机会显示其密钥类型和 SHA256 指纹，并提供 **接受并记住**、**仅接受本次** 或 **取消**（默认选中）；已更改或已吊销的密钥会被拒绝，并指出 `known_hosts` 中的对应行和 `ssh-keygen -R` 命令。`ssh_config` 按 OpenSSH 的方式读取——用户和系统文件、首个值优先、`!` 模式、`Include`——`sftp://` 的主机可以是 `Host` 别名，其 `HostName`、`Port` 和 `User` 均会生效。`ProxyJump` 按 `ssh -J` 的方式遵循，每个跳板主机都会被校验，且只用密钥或代理登录；`UserKnownHostsFile`、`GlobalKnownHostsFile`、`HostKeyAlias`、`HashKnownHosts` 和 `StrictHostKeyChecking yes` 均被遵守，`%h`、`%p`、`%r` 及其他标记都会展开。
- **崩溃的语言服务器会重启。** 过去已退出的服务器会一直保持停止状态，直到 termide 重启。现在它会在三分钟内最多重启三次，并把每个打开的文档重新发送给它，其间编辑器标题显示 `(restarting)`。命令面板和编辑器菜单中的 **重启语言服务器** 会立即重启它——也适用于启动失败的服务器，例如之后才安装了其可执行文件的情况。
- **终端中的 `ESC 7`、`ESC 8` 和 `ESC c`。** 终端面板会连同样式一起保存和恢复光标，并在保留回滚缓冲区的同时重置屏幕；带有中间字节的转义序列（如 `ESC # 8`）不再被当作其最后一个字节处理。

## 变更
- **`termide --detached` 会附加到它启动的实例。** 过去在分离的实例中工作需要两条命令，`termide --detached` 然后 `termide --attach`，而这几乎总是同一个意图。现在它启动实例后会立即附加，就像 `tmux new` 那样，并有简写形式 `-d`；`Alt+D` 或连接断开时，实例仍像以前一样继续运行，客户端会打印用于返回的 `--attach` 命令行。`--detached --no-attach` 保留旧行为，即启动实例并打印其 id，供脚本使用。没有可供附加的终端时，单独的 `--detached` 会在任何东西启动前被拒绝，并提示加上 `--no-attach`。
- **启动时重新打开上次运行的项目。** 过去每次启动后，要找回工作集都得用 `termide --restore` 或去一趟“项目”菜单。现在每次启动都会这样做：启动所在的目录成为当前项目，若它不在集合中则加入其中，上次运行的其他项目在其周围于后台打开，首次进入时才加载。与 `--restore` 不同，其中智能体未完成的工作——需要重试的失败请求、要继续推进的目标——会等到进入其项目时才进行，因此单纯的 `termide` 不会自行启动任何工作。其他实例已打开的项目留在那个实例中，而重新打开的项目只在首次加载时才被占用，因此第二个 `termide` 仍可以在其中之一启动；第一个实例随后会将其显示为划掉的样式。`general.restore_projects`（设置 → 常规 中的 **重新打开上次运行的项目**）可以关闭此功能，`--no-restore` 可跳过一次；设置关闭时 `--restore` 仍会恢复，并从上次运行所在的位置开始。给定了路径的启动——`$EDITOR`、`termide <dir>`——不恢复任何内容。
- **一个项目同时只在一个 termide 中打开。** 过去两个实例打开同一个项目时，会互相覆盖保存其布局、把它的语言服务器运行两遍，并且都会重试它遗留的失败智能体请求。现在，在另一个实例已打开的目录上打开、创建或移动项目会被拒绝，状态行会指出那个实例——它的 pid，或可供附加的分离实例。在这样的目录中启动 `termide` 会在界面出现前以同样的消息停止；当项目由分离实例持有且启动时有终端，则改为附加到那个实例，因此 `cd project && termide` 就能让你回到其中。重新打开上次运行的项目时，会跳过其他实例持有的项目。项目在关闭时或其 termide 结束时（包括崩溃）被释放，因为锁由操作系统持有。`$EDITOR` 启动、`--prompt` 和 `--recall` 不占用项目，永远不会被拒绝。
- **面板的暂停和停止会传达到每个委托。** 现在暂停也会挂起运行正在等待的委托；外部智能体的委托会被中断当前回合，并在暂停解除后在其自己的会话中继续，因此暂停背后不会有任何东西“仍在运行”。停止运行会停止它交出的每个任务，包括后台任务；它们的回答会等待你的下一个请求，而不会自行开始一个回合。
- **语法高亮随编辑更新，而不是从头开始。** 过去每次按键都会在 UI 线程上重新解析并重新高亮整个文件——在一个 820 KB 的 Rust 文件中每次按键约需一秒。现在每种语言，包括带有嵌入语言的语言（HTML、PHP、Markdown、JavaScript、Lua、Nix、Haskell），都只重新解析编辑所触及的部分，只高亮屏幕上的内容：在该文件中每次按键约需一毫秒。不超过 2 MiB（原为 1 MiB）的文件会整体高亮，字符串中的转义也不再把字符串的其余部分重置为默认颜色。
- **关闭终端会保留未保存的更改。** 过去关闭窗口、SSH 连接断开、`SIGTERM` 或 `termide --kill` 会让 termide 立即结束，丢失未保存的编辑和布局。现在它会像退出时一样关闭，先保留每一处未保存的更改，下次启动时这些更改会覆盖在文件之上重新打开；退出状态为 128 加信号编号。主循环失败时以状态 1 退出，并把错误输出到 stderr，因此 `EDITOR=termide git commit` 能察觉到。
- **智能体的只读命令受到更严格的判定。** 过去作为只读命令无需询问即可通过的命令，现在在读取项目之外的内容时会询问——无论是通过路径、通配符、符号链接、循环变量，还是跟随链接的目录遍历——或者在其 `sort`、`rg` 或 `git` 选项可以运行程序时询问；文件工具按其符号链接所指向的位置来判定，并且在 `all` 模式之外，对 `.git` 目录下的每次编辑都会询问。Shell 解析新增了对 `&`、反引号、单独的 `$` 以及会切换目录的循环的支持。项目的 MCP 服务器只按所显示的内容获得批准，其批准信息会列出它将收到的环境变量、请求头和 OAuth 客户端。

## 修复
- **外部智能体压缩期间输入的消息不再中止压缩。** 过去它会立即被引导进当前回合，从而中止 Claude Code 刚开始的压缩，Claude Code 之后又会再次运行压缩。现在消息会等到压缩结束，然后再加入回合。
- **较旧的 Claude Code 适配器的压缩显示为压缩。** 将压缩报告为 “Compact conversation” 步骤的适配器，过去显示为一个无名的 `think` 块；现在它显示为压缩，不带摘要，因此日志保持历史完整。
- **外部智能体压缩后的提示读起来更自然。** 过去它显示“保留最近 0 条消息”；现在不逐字保留任何内容的压缩显示为“已将 N 个令牌压缩为摘要”。
- **注定失败的智能体调试启动会立即失败。** 过去对不存在的命令、运行命令行调试器的命令、从焦点面板获取 `{file}` 的命令，或被传入未声明的参数、其字段无法容纳的值的命令执行 `debug` `start`，会先交给你或 `auto` 审查者——大约 16 秒的审查——然后才被拒绝。现在它会在询问任何人之前就被拒绝，理由相同。
- **Python 调试命令的参数能传到在终端中运行的程序。** debugpy 在终端面板中启动程序时，给它的是 termide 的环境而不是它自己的环境，因此命令的 `TERMIDE_PARAM_*` 值只到达了适配器，从未到达脚本。现在它们随启动一同传递。lldb-dap、GDB 和 Delve 本来就会把它们传下去。
- **智能体之间的消息送达它所针对的会话，而不是其面板当前显示的内容。** 过去智能体按编号写给面板，因此本应发给你已离开的会话的回答——你回到了会话列表，或打开了另一个会话——会在该面板中开启一个新会话，或落入一段无关的对话中。现在 `agents` 列出打开的会话，每个附有 id、智能体、状态、目录和面板，而 `send_message` 写给会话：送到它当前打开所在的面板，无论在哪里；当它没有在任何面板中打开时，消息在其日志中等待，不会开启新会话，并会告知发送方。再次打开该会话时会提示有多少条消息在等待，它们会随你在那里的下一个请求一同发送。后台任务的回答也以同样的方式送达交出它的会话。发送的消息显示为 `& 正在询问会话 1a2b3c4d · …`。
- **复述其指令的评判者不再终止 `/goal`。** 过去裁定取自第一个以裁定词开头的行，因此较弱的评判模型复述其提示——“`DONE` if the goal is fully achieved”——会悄无声息地放弃目标。现在裁定词必须单独位于回答的第一行，其后至多跟一个 `:` 或 `—` 及理由；其他任何形式都算作检查失败，会重试，然后暂停目标。评判者的提示不再以裁定词开头写行，以免被它复述。每个评判回答都会写入会话日志（`goal_verdict`：裁定、其理由或检查失败的原因，以及原始回答），目标已达成或被判定无法达成的会话在重新打开时会再次显示该提示。
- **保存永远不会留下写了一半的文件。** 编辑器、智能体的 `edit`、`write` 和撤销、布局以及未保存缓冲区的备份过去都是原地写入，因此崩溃或磁盘已满可能截断文件；现在它们会在旁边写一个副本，再重命名覆盖原文件，并保留符号链接和权限。只有少数 CRLF 行的文件会保留其大多数行所用的换行符，而不是整个变成 CRLF。无法读取的布局会被另存为 `session.toml.broken-<time>`，其未保存的缓冲区会被恢复，而不是被默认布局覆盖。因崩溃而在行中间被截断的智能体会话日志，现在可以再次完整读取。
- **文件操作在成功之前保留被替换的内容。** 过去经批准的覆盖会在复制前截断目标，若复制被取消或失败，原文件就丢失了；现在副本先落在其旁边，只有完成后才替换它。本地复制会保留修改时间和目录权限模式，Windows 上的跨卷移动会退回到复制再删除，而不是失败，两个远程到远程的传输也不再共用并删除彼此的临时目录。对远程文件执行另存为会留下一个普通的本地文件，过去下一次保存会把一个过时的副本上传覆盖远程原文件。十六进制编辑器不再覆盖更早的 `.bak`。
- **符号链接和奇怪的文件名不再让操作作用于其他文件。** 过去递归的 SFTP 删除会跟随指向目录的符号链接并清空其目标；归档解压可能通过一串链接被引导写到目标位置之外。名称不是有效 UTF-8 的文件会被当作另一个文件处理，遇到这样的名称时，git 状态会对整个仓库失效，或把已暂存的重命名显示为未知条目。悬空的远程符号链接会被当作空闲的名称，从而跳过覆盖询问。
- **输入到 shell 的内容不会运行超出其所指的东西。** 过去在目录切换器中选取名称含控制字符的目录，可能会擦除当前行并运行命令；现在控制字符会针对 bash、zsh、ksh 和 fish 进行转义，而对于无法转义它们的 shell，该行会被拒绝并给出提示。从文件管理器运行可执行文件时会给其路径加引号。数据库面板的密码不再写入保存的布局，在分离实例的终端中启动的 termide 也不再把自己当作被托管的那个实例。
- **终端面板的仿真。** 过去调整大小可能在已保存光标时让读取线程 panic；缩小会丢失提示符行，再放大后内容会被推到上方——现在各行会像 xterm 中那样移入和移出回滚缓冲区。不带计数的编辑序列（`dch1`、`il1`），以及位于滚动区域边缘的 `IL`/`DL`，按规范执行。过去停滞的同步更新会让面板永久冻结，未终止的 OSC 字符串会让内存无限增长，停止读取输入的程序会冻结整个界面，响铃循环会淹没宿主终端，自行退出的 shell 会一直是僵尸进程。
- **termide 保持响应。** 过去按住按键或移动鼠标会冻结终端输出、智能体流式输出和文件操作，直到输入停顿。`direnv` 在 UI 线程上运行，配合 nix-direnv 时会让屏幕冻结数秒，并且会弄乱其值中的反斜杠。撤销和重做不再从磁盘读取文件来判断缓冲区是否回到了已保存状态。监视机制经过重做：关闭同一仓库的两个面板之一不再停止对它的监视，访问过的目录会被释放，新的 `target/` 或克隆会在 UI 线程之外遍历且不处理其中被忽略的目录，嵌套仓库保持其监视，工作树和子模块能收到它们自己的 git 变更。
- **语言服务器和调试适配器无法让 termide 挂起或崩溃。** 过去声称长度巨大的消息会让 termide 中止，现在这是一个协议错误。已退出的语言服务器过去仍显示 `运行中`，并且每个请求泄漏一个线程，忽略关闭请求的服务器会冻结退出和项目关闭；现在请求会快速失败，关闭也有时限。调试会话不再因永远得不到回应的请求而显得忙碌。
- **智能体的工具保持在限度之内。** 过去对大文件的 `read` 会加载全部内容；`bash` 把所有输出保存在内存中；读取 `/dev/tty` 或管道会抢走 termide 的按键。现在读取只以流的方式读取请求的行，`bash` 保留有限的尾部并把其余部分转存到日志，终端和设备会被拒绝，外部智能体也在 termide 的终端之外启动。
- **编辑器中含组合字符的搜索和替换。** 过去替换 `नमस्ते` 或 `👍🏽` 的字面匹配会吞掉其后的文本，不区分大小写的 `i` 会匹配到 `İ` 内部；现在匹配以字素簇为单位计量，再映射回行中。
- **URL 中没有用户的 SFTP** 过去会通过一个新连接以本地用户身份列出主目录；现在它保留登录时自身的用户。
- **在面板组之间的分隔线上点击和拖动**，过去在面板组被挤压时会偏离分隔线实际绘制的位置。
- **“窗口”菜单显示智能体的快捷键。**
