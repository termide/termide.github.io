Gemini CLI 使用你的 Google 账号或 Gemini API 密钥运行。你可以在 termide 的某个终端面板里运行 `gemini`，但它只是待在 termide 旁边，而不是融入其中：它的修改绕过打开的编辑器直接写入磁盘，确认提示是它自己的，会话也不属于 termide。

termide 的代理面板可以改为在 Gemini CLI 上运行。模型、额度以及 Gemini CLI 自己的工作方式仍归 Google；权限卡片、会话列表以及跟随每次修改的编辑器则归 termide。本指南介绍如何配置，以及与在终端中使用 Gemini CLI 相比有哪些不同。

## 准备工作

- **Node.js**，并且 `npx` 在 `PATH` 中。Gemini CLI 自己就支持 [Agent Client Protocol](https://agentclientprotocol.com)，无需适配器：termide 通过 `npx` 以 `--acp` 运行 `@google/gemini-cli` 的最新版本。npm 缓存中的副本启动时不访问注册表；termide 每次运行时在后台检查一次新版本，新版本从下一个面板起生效。
- **已登录 Gemini CLI。** termide 本身不执行登录。如果你已经在用 Gemini CLI，就无需再做什么；否则单独运行一次 `npx @google/gemini-cli`，选择登录方式：Google 账号、Gemini API 密钥（`GEMINI_API_KEY`）或 Vertex AI。

## 添加连接

按 <Keys k="Alt+P" /> 打开设置，进入 **AI**。最上面是 **连接**。选择 **+ 添加连接**，在新连接的页面上把 **提供方** 设为 **Gemini CLI**。页面会去掉 Gemini CLI 用不到的字段——基础 URL、API 密钥、后备上下文窗口——在你命名之前，连接名为 `gemini-cli`。

<Shot src={models} alt="设置，AI › gemini-cli：提供方为 Gemini CLI，模型下拉列表展开：自动（由提供方决定）、Auto (Gemini 4)、gemini-4-pro-preview、gemini-4-flash-preview、gemini-3.5-pro、gemini-3.5-flash、gemini-3.5-flash-lite 和手动输入模型 id" caption="模型下拉列表列出 Gemini CLI 为你的登录提供的模型，其中包括它自己的 Auto。" />

页面上的其余项：

- **模型**：termide 会短暂启动 Gemini CLI，列出它提供的模型；加载期间字段中显示旋转指示。Gemini 自己的 **Auto** 为每个请求挑选模型；**自动（由提供方决定）** 把选择留给 Gemini CLI 的设置。这里选的只是预选模型：在面板中随时可以切换。
- **默认使用**：勾选后，新的代理面板都会在 Gemini CLI 上启动。

这里没有 **上下文窗口上限**：Gemini CLI 没有对应的设置，它按自己的规则压缩对话。

在 `config.toml` 中写法相同：

```toml
[ai]
connection = "gemini"        # 新会话使用的连接

[ai.connections.gemini]
provider = "gemini_cli"      # 其他都不是必需的
# model = ""                 # 留空：使用 Gemini CLI 自己的默认模型
```

## 第一个请求

按 <Keys k="Alt+A" /> 打开代理面板。横幅显示连接和模型；Gemini CLI 在后台启动期间，状态栏的 **模型** 标签会旋转，此时发送的请求会等待它就绪。之后面板的工作方式与其他连接相同：回答、推理和 Gemini 的步骤以块的形式出现——读取、带文件名的修改、带命令行的命令——打开了该文件的编辑器会跟随每次修改，运行计时一直走到 Gemini CLI 完成为止。

<Video src="/assets/blog/gemini-cli/gemini-cli.mp4" poster="/assets/blog/gemini-cli/gemini-cli.png" label="report.py 下方是连接 Gemini CLI 的代理面板：一个请求、一次读取、编辑器在第 14 和 15 行显示的修改、python3 -m unittest -q 的权限卡片（按 1 回答），然后是回答" caption="在 Gemini CLI 上发一个请求：编辑器标出改动的行，运行测试要等你回答。" />

**模型** 标签可以随时列出并切换 Gemini CLI 的模型，运行期间也可以。Gemini CLI 自己的 `/` 命令会加入面板的 `/` 列表，按原样发送给它。在它工作时输入的消息会在状态条中等待，作为下一个请求发送：Gemini CLI 不接受回合中途的消息。

## Gemini 的工具，termide 的决定

与 Codex 一样，Gemini CLI 保留 **自己的系统提示词和自己的工具**：它像在终端中一样读取、修改和运行命令，它自己的配置——`~/.gemini/settings.json`、它的 MCP 服务器和扩展、它的 `GEMINI.md` 上下文文件——依然有效。termide 增加的是：

- **权限模式。** termide 让 Gemini CLI 进入与面板模式对应的确认模式，并由 termide 决定 Gemini 请求确认的操作。
- **termide 的 MCP 服务器。** 它们的工具与 Gemini CLI 自己的工具一起提供给它，并像 Gemini 自己的调用一样接受检查。Gemini CLI 只在会话启动时读取一次工具列表，因此之后才连上的服务器要到下一个会话才可用。
- **Gemini CLI 没有对应物的工具**：用于搜索以往会话和 git 历史的 `recall`、在描述中列出你的技能的 `skill`，以及 `question` 和 `suggest_command`。

Gemini CLI 读取 `GEMINI.md`，而不是 `AGENTS.md`。如果你的项目把说明放在 `AGENTS.md` 中（termide 的其他连接都这样期望），可以在 `~/.gemini/settings.json` 中让 Gemini CLI 一并读取：

```json
{ "context": { "fileName": ["AGENTS.md", "GEMINI.md"] } }
```

对话循环仍由 Gemini CLI 负责：它自己压缩上下文，运行也无法在步骤之间暂停。

## 权限与 auto 模式

**权限** 标签（或 <Keys k="Shift+Tab" />）设置模式，termide 把它映射到 Gemini CLI 的确认模式上：

| termide | Gemini CLI |
| --- | --- |
| `ask`、`configured`、`auto` | `default`：修改和命令前都询问 |
| `plan` | 若 Gemini 的设置中开启了计划模式，则为 `plan`；否则为 `default`，修改由 termide 拒绝 |
| `edit` | `autoEdit`：修改直接通过，命令需询问 |
| `all` | `yolo`：什么都不问 |

Gemini CLI 请求确认的一切都要经过 termide 的检查：你的规则、你在本会话中给出的答复，以及模式。它们未能决定的操作会以卡片形式出现在输入框上方：允许一次、本会话允许、在本项目中始终允许或处处允许、拒绝、拒绝并告诉代理原因，或停止运行。

<Shot src={permission} alt="输入框上方的卡片：代理想运行 python3 -m unittest -q，选项有允许一次、本会话允许、拒绝、本会话拒绝、拒绝并告诉代理原因、停止运行" caption="Gemini CLI 通过 termide 的卡片询问，和 termide 自己的代理一样。" />

`auto` 适用于你信任其方向、但不想一张张回答卡片的运行。本该弹出卡片的操作会交给审查模型——一次独立的模型调用，判断这一步是否服务于你的请求。在 Gemini CLI 连接上，审查 **通过你的登录、在会话所用的模型上运行**，无需 API 密钥：termide 保持 Gemini CLI 运行，每次审查都在一个简短的独立会话中进行，不带工具，也不带代理的对话，因此代理永远不会评判自己。Gemini CLI 在那里也保留自己的系统提示词，因此审查比在模型连接上慢，并且计入你的额度。通常选一个小模型；在连接页面的 **auto 模式审查模型** 或 `[ai.auto_reviewer]` 中指定：

```toml
[ai.auto_reviewer]
connection = "gemini"   # 留空：会话自己的连接
model = "flash-lite"    # 该连接的某个模型，按 id、名称或其中一部分匹配
```

## 额度用完时

Gemini CLI 遇到额度错误时会先自己重试。放弃之后，它的 ACP 模式只报告 “Rate limit exceeded. Try again later.”——不带 API 给出的重置时间——因此卡片无法倒数：

- **立即重试**，
- **持续重试直到成功**，每次尝试之间等待更久，
- **停止**（<Keys k="Esc" />）。

<Shot src={limit} alt="错误 Rate limit exceeded. Try again later.（code 429）和卡片 Rate limit reached，选项有立即重试、持续重试直到成功、停止" caption="额度用完：Gemini CLI 不说明何时重置，因此卡片提供持续重试。" />

对于无人值守的 `/goal` 或 `/loop`，把 **遇到限额或中断时**（`[ai]` 下的 `on_limit`）设为 `wait`，运行会自行重试；`ask_else_wait` 会显示卡片，无人回应时则持续重试。这期间关闭 termide 也不会丢失任何东西：重新打开的会话会把卡片带回来。

如果不想等，可以准备第二个连接。卡片显示期间，状态栏的 **连接** 标签仍可点击：把会话切换过去，然后回答 **立即重试**。对话会一并带过去，另一个模型从 Gemini 停下的地方接着做。按密钥计费的 Gemini API 本身就可以作为这样的连接：

```toml
[ai.connections.gemini]
provider = "gemini_cli"

[ai.connections.gemini-api]
provider = "openai_compatible"
base_url = "https://generativelanguage.googleapis.com/v1beta/openai"
model = "gemini-3.5-flash"
api_key_env = "GEMINI_API_KEY"
```

## 委派任务

Gemini CLI 不运行 termide 的委派任务：它有自己的分工方式，其页面上的 **子代理** 显示 *(无)*。委派任务也不能在 Gemini CLI 上运行：这需要模型连接或 Claude Code。

## 会话与开销

会话日志记录 Gemini CLI 自己的会话，因此重新打开的面板会继续该会话，Gemini 了解完整的对话。从其他连接切换到 Gemini CLI 的会话，会先收到此前对话的记录。Gemini CLI 不能分叉会话，因此 `/goal` 的判定请求和 `/handoff` 的简报请求会作为一个回合发给它，面板及其日志不显示这个回合，但 Gemini 自己的会话会保留它。

**会话信息**（<Keys k="F3" /> 或 `/usage`）按花费者——对话、`auto` 审查等——和按模型细分 token 用量。Gemini 单独统计推理，因此 **推理** 一行会显示输出中有多少用于思考。

## 须知

- **termide 不提供沙箱。** termide 的权限是一种控制手段，而不是隔离：你允许的操作以你的权限运行，范围以 Gemini CLI 自己的沙箱为限（如果你开启了它）。
- **Claude Code 和 Codex 的接入方式相同**：`provider = "claude_code"` 或 `"codex"`。参见 [代理面板中的 Claude Code](/zh/blog/claude-code/) 和 [代理面板中的 Codex](/zh/blog/codex/)。
- **任何 OpenAI 或 Anthropic 兼容的 API 都可以作为备用连接**，额度用完时把会话切换过去：OpenAI、[OpenRouter](/zh/blog/openrouter/) 或 Anthropic 这样的托管 API，或你自己的服务器，使用 termide 自己的代理。[llama.cpp](/zh/blog/llama-cpp/) 和 [omlx](/zh/blog/omlx/) 是后者的两个例子。
- **详细说明** 见 [代理指南](https://github.com/termide/termide/blob/main/doc/zh/agent.md#配置模型)。
