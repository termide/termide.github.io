## 新增
- **CSV 和 TSV 文件以表格打开。** 在文件管理器中按 `F3`、通过“打开…”、书签或跟随链接，都会把分隔符文件显示为带列标题和单元格光标的网格；`Ctrl+E` 在编辑器中的源文本和表格之间来回切换。分隔符（`,`、`;`、`Tab`、`|`）以及第一条记录是否为标题行都会自动猜测，并可在状态栏或面板菜单中切换；点击列标题或按 `s` 对列排序——数字按数值排序——`y` 复制单元格，菜单可复制以制表符分隔的整行。文件不会载入内存：后台扫描找出各行的起始位置，只从磁盘读取屏幕附近的行，因此任意大小的文件都能立即打开，并可滚动、排序，拖动滚动条跳到文件中的任意位置。参见 [CSV 表格查看器](https://github.com/termide/termide/blob/main/doc/zh/csv.md)。
- **代理的终端会话。** `shell` 接受 `session`，在一个命名终端中运行命令，该终端在调用之间保留其目录、变量和后台任务；接受 `background`，启动一个耗时命令——开发服务器、监视器、缓慢的构建——并在其运行时返回；终端中超出超时的命令会继续运行，而不会被杀掉。新的 `terminals` 工具列出代理的终端，读取某个终端自上次查看以来的输出，向其中输入——文本和按名称的按键——并等待某段文本出现、shell 结束在其提示符处输入的命令（附带退出码）或输出静止，然后返回收到的内容（全屏程序则返回屏幕），显示终端的屏幕，中断其命令或关闭它，使代理能够驱动 REPL、调试器或交互提示。程序原地重绘的行（如 readline 的行）按屏幕显示的样子读取。每次请求之前都会提醒代理它打开的终端。终端属于代理会话并随之结束：当其面板关闭或切换会话、termide 退出，或子代理的任务结束时；子代理的终端属于它自己。`[ai] max_terminal_sessions` 限制每个会话的终端数（默认 10）。面板的状态条显示每个终端及其运行的内容，状态栏统计其数量；点击会在面板中显示该终端，你也可以在其中输入，关闭该面板则把终端交还给代理，并保持运行。
- **Claude 缓存对话。** Claude 只在被要求时才缓存提示，因此 Anthropic 连接现在会请求自动提示缓存，OpenRouter 连接对 Anthropic 的模型也会这样做：一次运行的每一步都从缓存中读取之前的对话，只需输入价格的一小部分，状态栏把这些 token 计入 `↻`。拒绝该字段的网关会收到不带该字段的重发请求。
- **Termide 在按应用统计用量的地方标明自己。** 按发送请求的应用统计推理用量的托管端点——目前是 OpenRouter——此前把 termide 的请求记在 `Unknown` 名下。现在连接会在那里标明 termide：以其名称和地址作为应用，并附上其类别。此项**默认开启**；设置中 AI 的连接页面新增 **以 Termide 身份标识**（`app_attribution`）用于关闭它，且该行只对进行这种统计的端点显示——本地的 llama.cpp、vLLM 或 Ollama 会忽略这些请求头，因此无需切换。服务上的应用页面由所有发送该地址的人共享，其用量公开可见，因此是否关闭由你按连接决定。

## 变更
- **代理的 `bash` 工具现在叫 `shell`。** 执行命令的工具以其用途命名，而不是以背后的 shell 命名。termide 会在它自己保存的内容中一次性完成重命名：全局配置和授予项目的规则中的 `[ai.permissions.bash]`、全局 `ai/hooks.toml` 中的 `tools` 以及全局代理的 `tools:`、会话日志中的调用；未改动的 `ai/tools/bash.md` 会被 `ai/tools/shell.md` 取代（改动过的会移过去，新的默认版本以 `.new` 放在旁边）。项目自己的文件不会被改写——其中留下的 `bash` 会被报告，并且仅在本版本中仍然生效。对脚本而言的变化：钩子的输入把工具命名为 `"shell"`，外部代理看到 termide 的工具为 `mcp__termide__shell`。
- **代理在你的 shell 中运行命令。** `shell` 和代理的终端使用终端面板所用的 shell——`terminal.default_shell` 或在系统中找到的那个——前提是它为 bash、zsh 或 fish，否则使用 bash；工具描述会向模型说明该 shell，终端会为它读取你的启动文件（`.bashrc`、`.zshrc`、`config.fish`）。在 Windows 上，找到 Git Bash 时就是 Git Bash。
- **修改过的连接会作用于已打开的面板。** 在设置中修改的连接此前只作用于之后打开的代理面板；已打开的面板会继续使用其开始时的端点、模型和窗口，直到重新打开。现在在该连接上打开的每个面板都会接受修改，并保留其对话；正在进行的运行会在旧端点上完成，并在该轮结束时切换。
- **状态条让新启动的项目保持可见。** 输入框上方，正在运行的子代理、移到后台的命令以及代理的终端此前按从旧到新列出，各显示三个，因此刚启动的项目最先被折叠进 `+N`。现在它们按从新到旧列出，各显示五个后再折叠最旧的；排队的消息仍按代理接收它们的顺序运行。
- **不对应任何工具的工具名会被报告。** 代理的 `tools:` 或钩子的 `tools` 中的名称，以及配置中的 `[ai.permissions.<tool>]` 表，如果不对应任何工具，此前会静默地不作用于任何东西；现在会在代理的横幅下或配置警告中报告。MCP 和插件的工具名以及通配符模式按原样接受。

## 安全
- **命令按运行它的 shell 的语法来判断。** 在 zsh 中，`*(e:'cmd':)` 这样的 glob 限定符和 `${(e)x}` 这样的展开标志被视为替换并会询问；在 fish 中，`(cmd)` 是命令替换，而规则无法整体读懂的 fish 命令——`switch`、`function`、`\x41` 这样的转义、here-document——总是询问，且不适用任何规则。
- **堵住了三种绕过“只读查看”检查的方式。** 代理只查看的命令无需询问即可运行，而一些会执行东西的命令也冒充了它们：bash 5.3 的 `${ cmd; }` 和 `${|cmd; }`，它们像 `$(…)` 一样运行命令；`test -v`、`[ -v ]` 或 `[[ … -eq … ]]` 比较中的数组下标，bash 即使在单引号内也会对其求值并进行替换（`test -v 'a[$(cmd)]'`）；以及 `find`、`sort`、`rg` 等命令中写有引号或反斜杠的选项（`find . -del''ete`）。现在它们都会询问。
- **变量的值不会未经询问就作为代码运行。** bash 会把某些值当作算术或提示符求值并执行其中的替换——`[ … -eq … ]` 等比较中不是数字的操作数、`test -v` 的变量、`${!x}`、`${x@P}`、由名称给出的下标或子串偏移（`${a[i]}`、`${s:i}`）——而终端会话会保留之前命令设置的值。现在这些都会询问，因此 `[ "$n" -gt 3 ]` 也会询问。
- **SSH 和 SFTP 升级到 russh 0.65**，避开了针对 0.64 的安全公告：未经确认的代理签名、构造的 `EXT_INFO` 和 `CONSTRAIN_CONFIRM` 消息导致的无限制内存分配、最大包大小为零时的通道停滞，以及 Pageant 帧缓冲。

## 修复
- **OpenRouter 模型按 ID 显示并使用回退窗口。** **模型** 标签现在在每个模型的 ID 旁列出 OpenRouter 给它的名称，`Context:` 会采用模型的 `context_length`（就像采用 vLLM 和 omlx 的 `max_model_len` 一样），而不是配置的回退值。
- **设置按 ID 列出 CLI 代理的模型。** Claude Code、Codex 或 Gemini CLI 连接的模型下拉列表以及显示所选模型的字段，现在显示代理给其模型起的名称；保存的仍是 ID。下拉列表也足够宽，能完整显示最长的选项，而不会截断。
- **Codex 的命令和编辑只描述了一半。** Codex 把命令作为其标题或单词列表发送，只在 locations 或 diff 中给出读取或编辑的文件，并仅凭 id 为已宣布的调用请求权限；这些调用显示时没有命令或路径，`auto` 也是在不知情的情况下判断权限请求。现在它们带有所运行和涉及的内容，并按其实际的编辑或命令来判断。
- **Gemini CLI 的花费统计有误。** 其缓存的输入被计算了两次，思考内容未计入输出；现在会话总计按与其他代理相同的方式统计。
- **Codex 或 Gemini CLI 的思考把主题显示成带星号的样子。** 每段思考开头的粗体主题（包括折叠后的标题）现在显示时不带标记。
- **流式工具调用只有在其 id 先到达时才保持同一标识。** 对于先发送工具调用名称、后发送其 id 的端点，调用的开始使用替代 id 发出，而其参数和结束带的是真实 id。现在三者带有相同的 id，消息保留服务器的 id。
