Termide 0.45 向你自己的程序开放，并让智能体委派出去的工作清晰可见。以下是主要变化；全部内容见[完整发布说明](https://github.com/termide/termide/releases/tag/0.45.0)。

## 插件

插件是放在全局 `config.toml` 旁边 `plugins/<name>/` 目录中的程序，附带一个写明其命令的 `plugin.toml`。Termide 为每个打开的项目在后台运行它，并通过它的 stdin 和 stdout 以 JSON-RPC 通信。插件可以：

- 获知文件的打开与保存、焦点、修改和 git 事件；
- 向命令面板和“命令”菜单添加命令，并配上自己的快捷键；
- 在状态栏显示条目，并打开由它发送的 Markdown 绘制的面板；
- 在编辑器中与语言服务器的诊断并列标记行，并响应补全、悬停提示和跳转到定义；
- 在 <Keys k="Ctrl+S" /> 写入文件之前修改它——保存时格式化只需要这一点；
- 为编程智能体提供自己的工具。

插件属于你，而不属于仓库。全局配置为每个插件设定模式：`on`、`opt-in` 或 `off`；项目的 `.termide/config.toml` 只能在该模式范围内切换它，因此你打开的任何仓库都无法唤醒你未允许的插件。反复崩溃的插件会以退避方式重启，一分钟内崩溃三次后便不再重启。

[插件指南](https://github.com/termide/termide/blob/main/doc/zh/plugins.md)介绍了协议，[`examples/plugins/`](https://github.com/termide/termide/tree/main/examples/plugins) 中有一个小型 Python 库，以及基于它的三个插件：`trim-on-save`、`todo-lint` 和 `word-count`。

## 看得见的委派任务

当智能体把任务交给另一个智能体时，这项工作不再在你看不到的地方进行。

- **实时查看。** 在任务块上按 <Keys k="o" />，或点击输入框上方的任务行，即可在布局之上实时查看子代理的每一步。在那里，<Keys k="F9" /> 把视图移入独立面板，<Keys k="Ctrl+T" /> 接管任务，**停止**则结束它。
- **暂停会挂起它。** 暂停面板现在也会挂起它分派出去的任务，`/continue` 之后它们从停下的地方继续。外部智能体运行的子代理无法挂起：它会继续运行，并单独计数。
- **退出后继续。** termide 退出时尚未完成的委派任务会标记为未完成。分派它的面板会提出继续，任务从自己的日志中恢复已完成的步骤，而不是从头开始。
- **它会询问你。** 子代理的权限请求会发到委派它的面板，而不再被直接拒绝。

单独的智能体现在可以把任务委派给自己的一个全新副本，用于获得干净的上下文或在后台工作；带有 `command` 的外部智能体也可以成为子代理。

## 从项目根目录运行命令

以前命令在获得焦点的面板所在目录中运行，所以每次切换目录后 `cargo test` 的含义都会变。在 `commands.toml` 中设置 `cwd = "project"`，或在命令表单中勾选 **Run from the project folder**（从项目文件夹运行），无论焦点在哪个面板，命令都会在项目根目录中运行。

## 以树形展示仓库

如果项目是一个按主机和团队分组存放多个检出的文件夹，git 面板的仓库下拉列表现在会以树形展示它们，并像文件树一样折叠。过滤器匹配路径，因此输入主机名或分组名即可找到其下的仓库。仓库发现也会多查找一层，并且不再把仅仅包含项目的仓库（例如覆盖整个主目录的 dotfiles 仓库）纳入列表。

## 更安全的项目

你打开的仓库不再能决定 termide 运行什么。项目配置不能设置调试器、语言服务器和 shell 的命令，也不能放宽智能体的模式和规则。项目的 MCP 服务器、钩子和命令在首次运行前会等待你的批准，“在此项目中始终允许”也保存在项目之外。

## 本版本的其他变化

- `web_search` 无需浏览器即可工作，通过普通 HTTP，适用于 Termux 和无图形界面的服务器。
- git 网络错误会指明仓库和服务器。
- 在没有 glibc 的系统上（Alpine、NixOS、32 位 Raspberry Pi OS），`install.sh` 会安装静态 musl 构建。
- 系统监视器以 MB 显示小于 2 GB 的内存。
