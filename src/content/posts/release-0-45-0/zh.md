## 新增
- **面板的暂停会一并停住它交出去的受托代理。** 暂停面板以前只停住面板自己的循环：受托代理会把任务一直做完，后台受托代理也照常运行，于是面板停在 `‖`，它的工作却在背后继续进行。现在每个任务都会在下一次请求或调用之前停下，并在暂停解除时——通过 `/continue`、`[▶]` 或撤回暂停——从停下的地方继续；放弃已暂停的运行或停止它，也会释放被停住的任务。状态条中的暂停行会数出它们（`‖ 已暂停 · 2 个等待中`），被停住的受托代理的视图也会在其按钮上方的横线上说明这一点。由外部代理运行的受托代理跑的是它自己的程序，任何暂停都无法让它停下：它会继续运行，单独计数（`· 1 个仍在运行`），只能停止。
- **委派的任务在 termide 关闭后依然保留，并由委派它们的面板继续。** 委派任务的日志现在会记录其运行的开始和结束，任务停在面板的暂停处时记为 `paused`，因此 termide 退出时尚未完成的任务会被识别为未完成，并在会话列表中显示为 `⏸ &`。负责继续它们的是委派它们的面板，因此面板把它们留在视野中，而不是打开新面板：每个未完成的受托代理在输入框上方占一行（`& task · 查找加载器 · search — 尚未完成`），单击该行会打开那个会话，由它自己的卡片询问。受托代理的面板不会自己打开。继续卡片上的 **继续** 会继续面板自己的工作，并连带它留下的每个受托代理：每个受托代理都在交出它的那个 `task` 调用之下于后台重新运行，从自己的日志中取回已做的步骤——做过的事都在那里，所以它是接着做而不是从头开始——结束后回答委派它的面板；它的权限请求以卡片形式送到那个面板。没有自己未完成工作的面板只就受托代理询问，此时 **继续** 只启动它们。**稍后决定** 让这些行留在原处，任务留在会话列表（`F6`）中；无法在此继续的受托代理会在询问的面板中说明。
- **从项目根目录运行的命令。** 命令以前在聚焦面板的目录中运行，因此每次切换目录后，同一行命令的含义就不同了：在深层目录的面板里，`cargo test` 只测试一个 crate，`./scripts/deploy.sh` 则什么也找不到。在 `commands.toml` 中设置 `cwd = "project"` 后，无论聚焦的是哪个面板，命令都在项目根目录中运行，在所有模式下（包括终端）都是如此，direnv 也从那里解析；不设置时，它仍像以前一样跟随聚焦面板。命令的创建和编辑表单中有一个 **Run from the project folder** 复选框，不必再手动编辑文件。命令在哪里运行属于其批准范围的一部分，因此把项目的命令移到另一个目录会重新询问。
- **按实际目录树显示项目的仓库。** 一个项目如果是按主机和团队分组的检出目录集合，以前会按文件夹名把仓库列成一个扁平列表，于是两个 `crm` 检出无法区分。现在 git 面板的仓库下拉列表用文件树的连线绘制这棵树：文件夹显示为暗色行，可用 `Enter`、`←`/`→` 或单击折叠，仓库位于其下；打开列表时会展开到当前仓库。与其中仓库同名的文件夹不会额外占一行，所有仓库都直接位于项目下的项目则保持扁平。收起的选择器显示项目内的路径，过滤也匹配该路径，因此输入主机名或分组名就能找到其下的内容。
- **代理可以委派给自己的副本。** 以前只有存在另一个使用 termide 自有循环、可接手工作的代理时才提供 `task`，因此像全新安装那样只有一个 `default` 代理时，根本没有 `task`。现在每个这样的代理都可以把任务交给自己的一个全新副本：为搜索提供干净的上下文，或在后台运行工作。受托代理本身仍然没有 `task`，因此委派不会嵌套。
- **无需浏览器的网页搜索。** 以前只有存在可运行搜索的 Chrome 系浏览器时才提供 `web_search`，因此在没有浏览器的地方——Termux、没有图形界面的服务器——代理完全无法搜索。现在没有浏览器时，会像 `fetch` 那样通过普通 HTTP 获取搜索引擎的结果页，因此只要设置了引擎就提供该工具。默认的 DuckDuckGo 可以这样工作；用 JavaScript 生成结果的引擎（Google、Bing）不会返回结果，调用会说明这一点。
- **实时观看受托代理的工作。** 在后台运行的任务以前在结束之前只在其块中显示几行。现在在它的块上按 `o`，或单击输入框上方它的那一行，会在布局之上显示它的视图，任何列都不会移动：随会话日志的增长显示受托代理的步骤，以及视图打开期间它向你提出的权限请求和问题。视图末尾是一排带按键的按钮：**在面板中 F9** 把视图移到独立面板中，**接管 Ctrl+T** 接管任务，**停止** 停止任务，后两者都需先确认，还有 **关闭 Esc**；跟随任务的面板则在其输入框边框上提供 `[✎]` 和 `[■]`。视图打开期间像模态窗口一样占据整个窗口；`Esc` 关闭视图，任务继续运行；任务结束后，视图按其结束时的样子显示，在面板中则会打开它的会话，可继续对话。
- **外部代理作为受托代理。** 带 `command` 的代理以前从不在 `task` 可交付工作的对象之列，文档中所说的“仅在面板中”也无从实现。现在它与其他代理一起列出，它的任务也像任何受托代理一样在后台运行：运行它自己的程序，为任务启动、随任务结束，使用自己的工具，进度显示在任务的块中，会话得以保留，权限请求则在委派面板中交给你。
- **单击即可查看所有正在运行的子代理。** 正在运行的子代理超过三个时，输入框上方的状态条只显示 `& +N`，别无其他。现在单击它会显示全部子代理，其后有一行 `& ▴`，用于把它们重新折叠起来。
- **插件。** 把程序复制到全局 `config.toml` 旁边的 `plugins/<name>/` 中，并配上为其命名的 `plugin.toml`，它就会为每个打开的项目在后台运行，并通过 stdin 和 stdout 以 JSON-RPC 通信：它能获知文件的打开和保存，向命令面板和 “命令”菜单添加命令，在状态栏中显示项目，根据它发送的 Markdown 打开自己的面板（`plugin:<action>` 链接是回到插件的按钮），在 termide 的窗口中提问——一个问题、一个选择、一行文本、一个表单——并以插件名作为标题，以免被当作 termide 自己的窗口，在编辑器中与语言服务器的诊断并列标记行，读取和编辑项目中打开的缓冲区（一次编辑是一个撤销步骤），打开文件和终端，获知焦点、更改、关闭和 git 事件，为自己的命令设置专属快捷键，发送通知，并为代理提供可报告进度的工具。它还可以在编辑器中与语言服务器并列提供补全、悬停提示、代码操作、跳转到定义和引用，或为没有语言服务器的语言提供这些功能；可以在 `Ctrl+S` 写入文件之前编辑它（`file/will_save`，保存时格式化），并获知代理运行的开始和结束。命令面板会显示插件的状态、重新读取插件目录并重启插件，设置中有一个“插件”标签页，用于设置插件的模式和项目的开关。全局 `config.toml` 为每个插件指定模式——`on`、`opt-in` 或 `off`——项目的 `.termide/config.toml` 只能在该模式范围内切换它，因此任何仓库都无法唤醒你未允许的插件。反复崩溃的插件会以退避方式重启，一分钟内崩溃三次后就不再重启。参见 `doc/en/plugins.md`；`examples/plugins/` 中有一个用于编写插件的小型 Python 库，以及用它构建的三个插件。

## 移除
- **`subagent_run` 以及在面板中运行的委派任务。** 委派任务在哪里运行以前是一项设置（`[ai] subagent_run`、设置中的 **委派任务运行位置**、`AGENT.md` 中的 `subagent_run`）：在后台、在空闲的代理面板中、在为它打开的面板中，或通过卡片询问。现在每个受托代理都在后台运行，在委派它的面板中向你询问其规则未作决定的事项，并在你需要时在你为它打开的面板中观看，因此该设置、它的卡片以及任务占用的面板都已移除。`config.toml` 中的该键会被忽略；在 `AGENT.md` 中，它会被报告为 termide 不读取的键。

## 变更
- **仓库发现限定在项目内部。** 现在会在项目根目录下三层（而不是两层）查找嵌套仓库和子模块，因此像 `<project>/<host>/<group>/<repo>` 这样的布局能列出其中的检出，而以前一个也列不出。包含项目的仓库——覆盖整个主目录的 dotfiles 仓库、上层的 monorepo——在找到项目自己的仓库后不再加入 git 面板的列表，以前它可能成为默认仓库；当根目录及其下都不是仓库时（例如在 `repo/src` 打开的项目），它仍会保留。
- **Git 网络失败会指明仓库和服务器。** fetch、pull 或 push 失败时以前只显示 `git fetch failed`；当一个项目中有许多位于不同服务器上的仓库时，现在会指明是哪一个：`git fetch services/api (gitlab.corp): …`。
- **后台任务在后台运行，不再占用面板。** 以后台方式交出的 `task` 以前会占用一个代理面板——空闲的，或在其他面板旁新开的——并在运行期间改变布局。现在它像调用所等待的任务一样在后台运行，并在委派面板的输入框上方占一行——显示受托代理、任务、它最近做的事以及时间——行上的 `✕` 经确认后停止它，单击则显示它的视图。委派面板自身的运行停止时，它的卡片仍然保留；关闭该面板或其项目会停止它的任务，确认时会数出任务数量。任务运行期间，面板的会话保持不变，就像运行期间一样：新会话、打开另一个会话或切换模型或代理，都要等它们结束。
- **在工具清单中勾选即可批准项目的 MCP 服务器。** 等待 `/trust` 的服务器以前在其标题右端有一个 `[✓]` 按钮，批准的同时会关闭清单。现在它的标题左侧有一个自己的复选框，未勾选（`[ ] MCP: ext`）；勾选后立即批准，清单保持打开：服务器连接，其工具出现在标题下方并处于启用状态，即使会话之前关闭了它们。其余按钮——`[↻]`、`[⇥]`/`[⇤]`——不再关闭清单：它们执行各自的操作，清单保持打开并随之更新。
- **状态条中每个运行中的行都可通过其 `✕` 停止。** 以前只有以后台方式交出的任务在输入框上方的行中有 `✕`；代理正在等待的子代理，以及代理移到后台的命令，只能通过停止整个运行来停止，子代理则还可以在其视图中停止。现在它们每个都有一个 `✕`，经确认后单独停止它，无论在哪里停止任务，确认的措辞都相同：它会指明受托代理，视图中的 **停止** 现在也是如此。
- **受托代理会向你询问，而不是被拒绝。** 在后台运行的委派任务以前只能做规则和模式已经允许的事：任何本该询问的操作都会被拒绝，尽管你就在委派它的面板里。现在它的权限请求会以常规卡片送到那个面板，像它的问题一样以 `& <delegate> ·` 开头，对 termide 自有循环和 Claude Code 副本都是如此；只有没有人可询问的 `termide --prompt` 运行仍会拒绝它们。并行工作的受托代理依次询问，一次一张卡片，而以前同时出现的第二个问题会被拒绝。你在本会话中授予受托代理的权限只对它的任务有效，也不会向它提供“始终”选项。

## 修复
- **恢复的 git 面板能看到整个项目。** 启动时按保存的布局重新打开的 git 面板，以前只列出它保存时所在的那个仓库，既没有项目的其他仓库，也没有它们所在的目录树；只有从菜单打开的面板才有。现在它会像新面板一样找到它们，并保持所选的仓库。
- **向上滚动仓库和分支列表时不再跳动。** 列表以前把光标固定在底边；现在窗口保持不动，只在光标离开时才移动。
- **Claude Code 面板的受托代理无法观看。** 在使用 Claude Code 的面板中，单击正在运行的任务的行或在其块上按 `o` 都没有反应：termide 的工具通过 MCP 为 Claude Code 提供服务，而 MCP 为每次调用分配了自己的 id，因此任务被登记在一个其块所没有的 id 之下。现在调用会采用代理宣告它时所用的 id，任务的视图也会像在使用 termide 自有循环的面板中那样打开。
- **启动失败的外部代理会说明原因。** 当它的程序立即退出时——`npx` 拒绝运行缓存副本丢失了可执行位的适配器、未登录、崩溃——面板、委派任务或 auto 模式的审查只显示 `initialize: the agent closed the connection`，原因则以 `debug` 级别写入日志。现在失败信息会以该程序打印的最后一行结尾，与调试适配器的做法相同：`initialize: the agent closed the connection: sh: …/claude-agent-acp: Permission denied`。
- **`工具` 标签与清单一致。** 关闭过某个 MCP 服务器工具的会话，以前会把这些工具全部从计数中扣除，无论是否提供：当该服务器尚未连接时恢复会话——项目的服务器正在等待 `/trust`，或已从配置中删除——会显示 `0/25`，而清单中的每个复选框都已勾选。现在该标签和横幅统计的是清单中的项目及其中已勾选的项目。
- **在没有 glibc 的系统上运行 `install.sh`。** 安装程序以前在 Linux 上总是选择 gnu 构建，而它需要系统的 glibc 加载器；在没有该加载器的系统上——以 64 位内核启动的 32 位 Raspberry Pi OS（`arm_64bit=1`）、Alpine、NixOS——安装的二进制文件会报错 “No such file or directory”。现在它会检查加载器，缺失时安装完全静态的 musl 构建。
- **系统监视器以 MB 显示较小的内存量。** 低于 2 GB 时现在以 MB 显示：一块约有 0.9 GB 内存的板子以前显示 `RAM 0/1GB`，因为按整 GB 计算时总量向上取整、用量向下取整。

## 安全
- **拒绝不受信任的 emSign 证书。** termide 用于 HTTPS 和 FTPS 的 TLS 栈——代理的连接和网页工具、FTPS 文件管理器——以前可能接受经由不受信任的 emSign 中间证书的证书链，而这些证书的私钥现已公开（RUSTSEC-2026-0381、RUSTSEC-2026-0382）。现在会拒绝它们。
- **项目配置不能再指定 termide 运行什么，也不能放宽代理的权限。** `.termide/config.toml` 随仓库一起提供，它以前可以设置调试器或 LSP 服务器的 `command` 和 `args`、终端的 `default_shell`、网页工具的 `chrome_path`、日志的 `file_path`、连接的 `base_url` 和 `api_key_env`（把任意变量中的密钥发送到任意服务器），以及代理的权限 `mode` 和 `allow` 规则。现在这些只从全局文件读取；在项目文件中它们会被忽略，并在日志中记录一行，设置窗口在保存到项目时会将它们显示为在全局设置中设置。项目仍然可以让代理询问或拒绝。从菜单中选择的 shell 现在保存在全局配置中。
- **项目的 MCP 服务器和钩子需等待批准。** 来自项目 `mcp.toml` 或任何 `.mcp.json` 的服务器，以及来自项目 `hooks.toml` 的钩子，以前会在代理面板打开时自行启动。现在它们会等待：面板会说明每一项将运行什么，`/trust` 列出它们，`/trust <name>` 按其当前配置批准其中一项，批准保存在 termide 的数据目录中；其命令、参数、环境或地址一旦更改，就需要再次等待批准。项目也不能再关闭或替换你自己的钩子。
- **项目的命令在首次运行前会询问。** 项目 `commands.toml` 中的命令以前一经选中或按下其快捷键就会运行——而仓库可以把命令绑定到任意按键，包括普通字母，因此在编辑器中打字就可能运行它。现在它首次运行时会显示要运行的内容（包括其 `build`）并询问；批准保存在项目之外，只要命令保持不变就一直有效；在批准之前，只有按住 `Ctrl` 或 `Alt` 的快捷键或 F 键才会询问，用于输入文本的按键只有在命令获得批准后才会绑定。在 termide 自己的表单中编写的命令在保存时即获批准。
- **项目的代理不能放宽模式或启动程序。** 项目 `.termide/ai/agents/` 下的 `AGENT.md` 以前可以以 `all` 模式启动——而模型可以自行委派给它——或者是一个外部代理，选中时 termide 会运行它的 `command`。现在项目的代理只能以 `plan` 或 `ask` 模式启动，外部代理只能在配置的 `agents/` 中定义。
- **搜索引擎只来自配置。** 项目的 `ai/web/engines/<name>.toml` 以前可以重新定义引擎，把代理的网页搜索发送到仓库选定的服务器；现在只读取配置中的引擎。
- **“在此项目中始终允许”保存在项目之外。** 该规则现在写入 termide 数据目录中的 `trust/<project path>/permissions.toml`，而不是项目的 `.termide/config.toml`。旧版本写在那里的规则现在会被忽略，因为 termide 无法区分哪些是你的、哪些来自仓库：请重新回答一次“始终允许”，或把它们移到全局文件中。
