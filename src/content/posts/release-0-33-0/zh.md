## 新增
- 设置中现在提供 **数据库** 和 **查看器** 两个快捷键分区。此前该窗口只列出了配置中定义的九个分区中的七个，因此数据库面板的六个快捷键和查看器的两个快捷键只能通过手动编辑 `config.toml` 来修改。

## 变更
- **git diff 面板改为在后台加载**。它以前在 UI 线程上运行两次 `git status`，再为每个变更文件各运行一次 `git diff`——而且不只在打开时：面板会在文件系统和 git 事件发生时刷新，所以在仓库任意位置编辑文件，都会让界面在每次监视器触发时卡住。在缓存已预热的情况下测得，四个变更文件耗时 90 ms，三十个则为 360 ms。现在面板会立即打开，标题中显示加载标记，并在新 diff 加载期间继续显示之前的 diff。
- **语言服务器只接收发生变化的范围。** 以前每次按键都会发送整个文档，这需要分配一份文件副本并遍历整个缓冲区——其开销随文件大小而不是编辑量增长，在数 MB 的文件上相当明显。在范围不可信的情况下仍会发送整个文档：对于只声明支持完整同步的服务器、从磁盘重新加载之后，以及积压了大量未发送变更时。
- 贡献者检查现在还会检查未使用的依赖声明（`cargo machete`），并通过 `cargo nextest` 运行测试，使整个工作区的测试套件从 21.5 秒缩短到 4.1 秒。pre-commit 钩子检查的是实际暂存的内容而不是工作树，因此把一次工作拆分成多个提交时不再需要 `--no-verify`。

## 修复
- 只要同一行前面有 emoji、组合重音符号或 ZWJ 序列，**悬停提示、补全、跳转到定义、查找引用和重命名就会向语言服务器询问错误的标记**。编辑器的列按字素簇计数，而语言服务器协议按 UTF-16 码元计数，此前一个被当成另一个传递了；两者在 ASCII 和整个基本多文种平面内是一致的，这就是普通文本和西里尔字母不受影响的原因。补全自身的文本编辑也以同样方式被误读，可能替换错误的范围。
- **打开 SFTP 书签可能导致整个应用崩溃。** SFTP 后端启动失败时，会在最先触及它的线程上 panic，而这个线程就是界面线程；现在它会以连接错误的形式呈现。
- **取消文件复制会留下一个被截断的文件**，看上去却像已完成的文件。现在除非复制完成，否则会删除目标文件。请注意，取消一次*覆盖已有文件*的复制现在会删除该文件：它在复制开始时就已经被破坏，而一个冒充完整副本的残片比没有文件更糟。
- **在 SFTP、FTP 或 SMB 共享上创建文件或目录会让界面卡住**，时长等于一次往返——在服务器无响应时最长可达后端三十秒的超时。现在条目会在服务器响应后出现，界面在此期间仍可使用。
- **双击 `some_long_name` 只会选中 `some`。** 单词选择把 `_` 当作分隔符，而本编辑器自己的 vim 移动命令和终端的双击都已将其视为单词的一部分。
- 一年或更早的时间戳在孟加拉语、印地语、印度尼西亚语、日语、韩语、泰语、土耳其语、越南语和中文中会回退为英文：这九种翻译中缺少 `year` 的复数形式。
