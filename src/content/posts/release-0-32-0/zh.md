## 新增
- 针对终端无法传递的快捷键的启动诊断。在 macOS 上，termide 会报告有多少个 `Alt+<key>` 快捷键因 Option 键的文本组合而失效，并列出仅绑定到功能键的操作，每一项都附有在当前终端中修复它的设置。
- `general.report_all_keys`（仅 macOS，默认开启）——请求终端把每个按键都以转义码报告，这正是让 `Alt+<letter>` 快捷键在 macOS 上可用的关键。如果你需要在 termide 中使用死键或输入法组合输入，请将其关闭。

## 变更
- macOS：在支持 Kitty 键盘协议的终端（Ghostty、kitty、WezTerm、iTerm2 3.5+）上，`Alt+<letter>` 快捷键开箱即用。以前这约 25 个快捷键全部被 Option 的文本组合吞掉。
- 持续集成现在在 macOS 和 Linux 上都运行完整的格式/lint/测试检查。以前 macOS 只在发布时构建，因此平台回归无法在打标签前被发现。

## 修复
- **另存为、重新加载、重做、在文件中搜索和在文件中替换**（`Ctrl+Shift+S`、`Ctrl+Shift+R`、`Ctrl+Shift+Z`、`Ctrl+Shift+F`、`Ctrl+Shift+H`）在任何实现了 Kitty 键盘协议的终端上、在所有平台上都从未生效过。
- **查找引用**无法在 xterm 风格的终端上通过其 `F24` 备用键触发：读取快捷键绑定时，F12 以上的功能键会被拒绝。
- macOS：文件监视器在任何实际项目上都会耗尽文件描述符并导致其线程崩溃，面板还会循环重新执行 git status——表现为面板标题中大约每秒出现一次加载指示。
- macOS：终端面板显示的是它被打开时所在的目录，而不是 shell 的当前目录；标题中缺少正在运行的命令；也从未察觉到正在运行的进程——因此关闭忙碌的面板时不会请求确认，而“在此处打开”、目录切换器和 git 面板的仓库搜索都基于错误的目录。
- macOS：资源监视器完全不列出任何磁盘。
- macOS：打开指向文件或 URL 的书签没有任何反应。
- 通过设置重新绑定按键时，可能会保存一个任何按键都无法匹配的组合键，这在 macOS 上的 `Alt+<letter>` 中最为明显。

## 安全
- 远程连接诊断不再把账户的用户名写入日志。有两条 `VfsManager` 错误消息打印了原始的提供方查找键，其中包含用户名；现在它们使用与代码库其他部分相同的脱敏形式（`sftp://***@host:port`）。密码从未被记录过。
