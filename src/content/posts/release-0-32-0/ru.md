## Добавлено
- Диагностика при запуске для сочетаний клавиш, которые терминал не может передать. На macOS termide сообщает, сколько привязок `Alt+<key>` теряется из-за того, что Option набирает символы, и перечисляет действия, привязанные только к функциональной клавише, — для каждого указана настройка, которая исправит это в текущем терминале.
- `general.report_all_keys` (только macOS, включено по умолчанию) — просит терминал сообщать о каждой клавише escape-последовательностью, благодаря чему там становятся доступны сочетания `Alt+<letter>`. Отключите, если вам нужен ввод через мёртвые клавиши или IME внутри termide.

## Изменено
- macOS: сочетания `Alt+<letter>` работают сразу в терминалах с протоколом клавиатуры Kitty (Ghostty, kitty, WezTerm, iTerm2 3.5+). Раньше все ~25 из них поглощались набором символов через Option.
- Непрерывная интеграция прогоняет полный набор проверок форматирования, линтера и тестов на macOS так же, как на Linux. Раньше macOS собиралась только при релизе, поэтому платформенные регрессии нельзя было поймать до тега.

## Исправлено
- **Сохранить как, Перезагрузить с диска, Повторить, Поиск в файлах и Замена в файлах** (`Ctrl+Shift+S`, `Ctrl+Shift+R`, `Ctrl+Shift+Z`, `Ctrl+Shift+F`, `Ctrl+Shift+H`) никогда не работали ни в одном терминале с протоколом клавиатуры Kitty, на любой платформе.
- **Найти все ссылки** нельзя было вызвать запасной клавишей `F24` в терминалах в стиле xterm: функциональные клавиши выше F12 отвергались при чтении привязки.
- macOS: наблюдатель за файлами исчерпывал файловые дескрипторы на любом реальном проекте и ронял свой поток, а панели запускали git status в цикле — это было видно по спиннеру, появлявшемуся в заголовках панелей примерно раз в секунду.
- macOS: панель терминала показывала каталог, в котором её открыли, а не текущий каталог оболочки, не показывала в заголовке запущенную команду и не замечала работающий процесс — поэтому закрытие занятой панели не спрашивало подтверждения, а «открыть здесь», переключатель каталогов и поиск репозиториев в git-панелях работали не из того каталога.
- macOS: монитор ресурсов не показывал ни одного диска.
- macOS: открытие закладки, указывающей на файл или URL, ничего не делало.
- Переназначение клавиши через настройки могло сохранить сочетание, которому не соответствует ни одно нажатие, — заметнее всего для `Alt+<letter>` на macOS.

## Безопасность
- Диагностика удалённых подключений больше не пишет имя пользователя учётной записи в журнал. Два сообщения об ошибках `VfsManager` выводили необработанный ключ поиска провайдера, в который входит имя пользователя; теперь они используют ту же скрытую форму (`sftp://***@host:port`), что и остальной код. Пароль никогда не записывался в журнал.
