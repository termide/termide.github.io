## 新增

- **在文件管理器中打开 SMB 和 NFS 共享。** `smb://[user@]host/share/path` 通过 SMB 2 或 3 打开 Windows、Samba 或 NAS 共享，`smb://host/` 列出服务器上的共享；登录被拒绝时会询问密码，并可将其保存在保险库中，`DOMAIN;user` 用于指定域。`nfs://host/export/path` 打开 NFSv3 导出，`nfs://host/` 列出所有导出。两者都是内置的，不需要系统库，也不需要挂载：文件可以打开、在面板之间复制和移动，单个文件或整个目录的上传和下载都带有进度、暂停和取消。只接受特权端口或需要 Kerberos 的 NFS 导出会被拒绝，并附上说明：应在服务器上修改什么，或改用系统挂载。参见[远程文件系统](https://github.com/termide/termide/blob/main/doc/zh/vfs.md#smb-与-nfs)。
- **git diff 面板可暂存、取消暂存和丢弃一个块或若干行。** 光标在差异的各行间移动：`Space` 暂存光标所在的文件、块或行，或用 `V` 或 `Shift+↑↓` 选中的行，在已暂存一侧则取消暂存；`D` 在确认后从工作区丢弃它们，面板打开期间 `U` 可恢复上一次丢弃；`[` 和 `]` 在块之间跳转。未跟踪、重命名和二进制文件按整个文件处理。在这里 `Space` 不再折叠文件（改用 `Enter`），提交或 stash 的差异除外。参见[界面](https://github.com/termide/termide/blob/main/doc/zh/ui.md)。
- **在 diff 面板中审查代理的更改。** `/changes`（或代理面板菜单中的 **审查更改**）打开 git diff 面板，显示代理自你上次接受以来所做的更改，你在两次请求之间自己的编辑不计在内。`Space` 保留一个片段或若干行，`D` 拒绝它们——它们会在工作区中撤销，代理会在下一个请求中得知——`U` 撤回上一次拒绝，`A` 和 `X` 保留或拒绝全部更改；暂存或提交某项更改也会保留它。每个请求都会把工作区快照到任何日志都看不到的 git 树中，因此 shell 命令和外部代理（Claude Code、Codex、Gemini CLI）也都涵盖在内。你也编辑过的文件会被标记，未经你要求绝不会被拒绝。参见[界面](https://github.com/termide/termide/blob/main/doc/zh/ui.md)和[代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md)。
- **在编辑器中暂存、取消暂存和还原更改。** `F7` 和 `Shift+F7` 在边栏标记的更改之间逐个跳转；在更改过的行或选中的行上，面板的 `[≡]` 菜单可按编辑器中当前的内容（无论是否已保存）暂存该更改、取消暂存已暂存的更改，或把这些行还原为索引中的版本——这是一次普通编辑，可用 `Ctrl+Z` 撤销。已暂存更改的行号以空心样式绘制——颜色只在数字上，没有背景——从而区分已暂存和未暂存的更改。对应的操作是 `[editor.keybindings]` 下的 `stage_change`、`unstage_change` 和 `revert_change`，没有默认按键。参见[编辑器](https://github.com/termide/termide/blob/main/doc/zh/editor.md)。
- **编辑器可折叠代码块。** `Alt+,` 折叠光标所在的最内层代码块，再按一次则折叠包住它的那一层；`Alt+.` 或单击边栏中的 `▸` 将其展开，折叠的行以 `⋯ N lines` 结尾。**全部折叠** 和 **全部展开** 位于面板的 `[≡]` 菜单中（`[editor.keybindings]` 下的 `fold_all`、`unfold_all`，没有默认按键），Vim 模式提供 `za`、`zc`、`zo`、`zM` 和 `zR`。代码块来自语言服务器的折叠范围；没有语言服务器或它回答太慢时则按缩进确定（它迟到的回答用于下一次折叠）。光标会跳过折叠区，搜索或跳转落在折叠区内时会将其展开。参见[编辑器](https://github.com/termide/termide/blob/main/doc/zh/editor.md)。
- **终端了解 shell 的命令。** 终端面板中的 bash、zsh 和 fish 会标记每个提示符和命令（`OSC 133`），同时仍读取你自己的启动文件。`Ctrl+Shift+Up` / `Ctrl+Shift+Down` 在提示符之间跳转，失败的命令会在面板左边框上标出，面板菜单中的 **复制命令输出** 复制上一条命令的输出，**发送给代理** 和 `@term` 交出的是上一条命令及其输出和退出码，而不是屏幕的最后几行。`[terminal]` 下的 `shell_integration = false` 可将其关闭。参见[终端](https://github.com/termide/termide/blob/main/doc/zh/terminal.md#shell-集成)。
- **代理把部分工作分叉到单独的面板中。** 新的 `fork` 工具把代理的会话复制到一个新的代理面板中，副本以代理为它写下的那部分工作作为第一个请求。若指定了 `focus`，副本会先围绕它进行压缩，从而以与其任务相关的内容开始，而不是整个历史。副本以它自己的任务命名——代理给出的 `title`，或其请求的第一行——该名称就是其面板的标题，因此同一会话的多个分叉可以区分开来。与子代理不同，分叉从一开始就归你所有：它和其他会话一样，遵循面板的常规规则，不回报结果，模型调用次数也不受限制，一直保留到你关闭其面板。在 `ask` 模式下它会询问，在计划模式下会被拒绝，其第一个请求计入代理之间不经过你相互传递的消息数。参见[把部分工作分叉出去](https://github.com/termide/termide/blob/main/doc/zh/agent.md#把部分工作分叉出去)。
- **代理以卡片形式提议目标或循环。** 代理不再写出一行 `/goal` 或 `/loop` 让你粘贴，而是用新的 `suggest_goal` 和 `suggest_loop` 工具把它放在卡片上：目标，或循环的提示、运行频率和结束条件，提议的理由，以及它将取代的正在进行的目标或循环。**开始** 像输入该行一样启动它，**先编辑** 把该行放入输入框，**不开始** 或 `Esc` 则拒绝；没有卡片，什么都不会启动。Codex 和 Gemini CLI 除 `suggest_command` 之外也会获得这两个工具。参见[工具](https://github.com/termide/termide/blob/main/doc/zh/agent.md#工具)。
- **循环在满足条件时结束，或由代理停止。** `/loop [interval] <prompt> until: <condition>` 让 `/goal` 的评判在每次运行后检查条件：满足时，循环结束并给出原因；无法达成时，循环结束并给出警告；否则下一次运行按计划进行。代理的 `jobs` 工具在 `loop` 下列出面板的循环，并在不再需要时将其停止，同时给出相应通知——而不是让它一直运行到 100 次的上限。
- **查看代理在各会话和各项目中的花费。** 会话信息（`F3`、`/usage`）变为用量窗口：除 **此会话** 外，**项目** 和 **所有项目** 汇总今天、7 天、30 天或全部时间内的每个会话——token、缓存命中，按来源、模型、代理和项目分列，花费最多的十个会话（可从列表中在其所属项目中打开），以及该时段内每天一根柱形，全部时间则每月一根。**AI → 用量…** 无需代理面板即可打开它。日志只统计一次并保存在缓存中，之后只重新读取有变化的日志。十亿及以上的 token 数显示为 `B`。参见[编码代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md#跨会话用量)。
- **代理在编辑之后能看到语言服务器报告的错误。** 在 `edit` 或 `write` 之后，文件的语言服务器会得知这次更改，它报告的错误会附加到工具的结果中——已知更改前该文件的错误时只附加新错误，最多 20 条，警告不计在内。没有编辑器打开的文件会为这次检查在其语言服务器中打开，必要时启动服务器；结果最多等待 5 秒。使用 termide 工具的 Claude Code 也会得到同样的结果。参见[编码代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md#工具)。
- **把编辑器中的选区或终端输出交给代理。** `@selection` 和 `@term` 位于代理 `@` 列表的最前面：你最后使用的编辑器中的选区，以及终端的选区，没有选区时则是终端的最后 200 行。每一项以 `[#2 selection src/main.rs:10-24]` 这样的占位符进入输入框，保存当时的文本，发送时连同一行说明其来源的文字一起插入。编辑器的 `[≡]` 菜单（选中文本时）和终端的菜单提供 **发送给代理**，将其放入最后使用的代理面板（或一个新面板）并聚焦该面板；`send_to_agent` 可以绑定到按键。参见[编码代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md)。
- **移动或复制项目，连同 Termide 为其保存的一切。** 在 `Projects` 菜单中或在项目菜单栏按钮的菜单中，对项目按 `F6` 会移动项目目录，按 `F5` 则复制它。其保存的布局、未保存的缓冲区、代理会话及其检查点和断点都会随之迁移，移动时还会带上授予它的权限。文件通过后台操作传输。打开的项目会为移动而关闭，并在新路径上重新打开。副本在原项目旁边于后台打开，拥有自己的会话 ID，不带任何已授予的权限。对于标有 ✗ 的项目（其目录已在 Termide 之外被移走），`F6` 或 `Enter` 会询问它现在的位置，并把同样的状态迁移过去，不移动任何文件。
- **Vim 模式显示前缀之后可接的按键。** 在 `g`、`z`、`Ctrl+W` 或 `d` 这样的操作符（带或不带计数）之后，编辑器右下角会出现一个框，列出可以补全命令的按键及其作用；按下一个键后它就会消失。参见[编辑器](https://github.com/termide/termide/blob/main/doc/zh/editor.md)。
- **`/fork <focus>` 带焦点分叉。** 副本打开时已围绕该焦点压缩，就像 `/compact <focus>` 那样，而被分叉的面板保持原样；单独的 `/fork`、`F5` 和菜单项仍像以前一样分叉整个对话。
- **`/goal` 评判、`/handoff` 简报和子代理各自可使用独立的模型。** 附带的工作采用统一的选择方式：`[ai.goal_judge]`、`[ai.handoff]` 和 `[ai.subagents]` 与 `[ai.auto_reviewer]` 并列，各自指定一个连接及其模型，留空则使用会话的模型——也可在设置窗口的 AI 标签页中设置。连接的 `reviewer` 和 `subagents` 接受同样的表，或像以前一样接受连接名称，并且优先生效。评判和简报适用于 termide 自己的循环；CLI 代理会自己完成这两项。参见[配置模型](https://github.com/termide/termide/blob/main/doc/zh/agent.md#配置模型)。
- **代理之间不经过你相互传递的消息数上限成为一项设置，并在拒绝前先询问。** `[ai]` 下的 `max_agent_messages`（也在设置窗口 AI 页面的“权限”下）设置数量——默认仍为 10，`0` 表示不限制；已打开的面板会立即采用更改。超过上限时，代理会在卡片上询问你是否再允许同样多的消息，这会像你自己发送的消息一样重新开始计数；停止或关闭卡片则像以前一样拒绝该消息。参见[代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md)。
- **连接可以限制单次模型调用的推理量。** 连接上的 `reasoning_budget`（也是设置窗口中该连接页面上的 **推理预算（token）**）限定单次调用可用于推理的 token 数：推理超出它的模型会在此处被截断，并立即在不推理的情况下重新请求（对于无法停止推理的模型，则以最低推理强度；第二次截断会停止运行），而不是推理好几分钟，直到输出上限把它截断而一无所获。对于接受思考预算的 Claude 模型，请求本身也会要求不超过该数量。默认值 0 表示不限制；仅适用于 termide 自己的循环。参见[代理](https://github.com/termide/termide/blob/main/doc/zh/agent.md)。
- **终端的回滚长度成为一项设置。** `[terminal]` 下的 `scrollback_lines`（也在设置窗口的“终端”页面上）设置终端在屏幕上方保留多少行——默认仍为 10,000，`0` 表示不保留；更改之后打开的终端会采用它。参见[终端](https://github.com/termide/termide/blob/main/doc/zh/terminal.md)。
- **设置窗口新增四项设置。** “常规”页面在“输入”下新增 *Option 作为 Alt（macOS，重启后生效）*（`general.report_all_keys`），在“外观”下新增 *git 日志中的制表符图形*（`git_log.unicode_graph`）；已打开的 git 日志会按所选样式重新读取。AI 页面在“权限”下新增 *每个智能体的终端会话数*（`ai.max_terminal_sessions`），在“通知”下新增 *智能体等待你时提示音*（`ai.bell_on_attention`）。
- **`--output stream-json` 显示一次运行把时间花在了哪里。** 每一行都带有 `elapsed_ms`，即自运行开始以来的时间；`tool_result` 带有工具 `output` 的前 2000 个字符；最终的 `result` 在最后一次回答的 `usage` 旁边新增 `usage_total`，即整次运行的 token。推理内容在模型写出时以 `thinking` 行输出，超过 4000 个字符的调用参数以 `tool_input` 行输出，因循环而被截断的调用以 `loop` 行输出，触及输出上限却没有任何内容的回复以 `cut_off` 行输出，因此因超时而被终止的运行仍能显示其最后一次调用在做什么。参见[无界面模式](https://github.com/termide/termide/blob/main/doc/zh/agent.md)。

## 变更

- **计划按你进入计划之前所用的模式执行。** 计划卡片的前两行此前会切换到 `edit`，而它会搁置已配置的 `allow` 规则，因此计划中的每条命令都会询问，即使是已被永久允许的命令。现在它们会回到你在计划模式之外最后一次发送消息时所用的模式（例如 `auto`），并在该行上写明；通过 `Shift+Tab` 切换到计划模式途中经过的模式不算在内。从 `ask` 进入时，或在以计划模式开始的会话中，它们会切换到 `configured`。接受编辑仍作为第三行提供，单独的“已配置规则”一行已移除。
- **项目按钮打开项目菜单。** 菜单栏中的项目按钮会打开该项目的菜单，就像菜单项打开其下拉菜单一样——单击当前项目的按钮，或用 `←`/`→` 移到任意按钮上即可：切换到项目、移动、复制和关闭。即使只打开了一个项目，也会显示该按钮。
- **写出的页面从其路径下方的一行打开。** `write` 一个 HTML、Markdown 或 Mermaid 文件时在其标题下添加的那一行，现在显示为 `Open in HTML ↗`，像链接一样暗淡并带下划线，位于文件路径下方，而不再以强调色重复文件名。
- **文件管理器中的 `Delete` 把文件移到回收站。** `Delete` / `F8` 在一次默认选中“是”的确认后，把选中项移到系统回收站（macOS 废纸篓、freedesktop.org 回收站、Windows 回收站）；新的 `delete_permanently` 操作 `Shift+Delete` / `Shift+F8` 在一次默认选中“否”的确认后永久删除。远程位置没有回收站：在那里 `Delete` 会永久删除，其确认提示也会这样说明。参见[文件管理器](https://github.com/termide/termide/blob/main/doc/zh/file-manager.md)。
- **每个项目的状态保存在一个文件夹中。** Termide 为项目保存的所有内容现在都位于其数据目录中的一个扁平文件夹 `projects/<name>-<hash>/` 里。其中包括 `project.toml` 中的布局和根目录、`trust.toml` 中已授予的权限和批准、实例锁、`logs/` 中的运行日志，以及 `buffers/` 中未保存的缓冲区。代理会话仍位于 `ai/sessions/` 下。旧的 `sessions/`、`trust/` 和 `locks/` 目录树以及镜像路径的 `projects/` 目录树会在首次启动时合并进来。与新版本同时运行的旧版本 Termide 看不到它的锁，因此两者可能把同一个项目打开两次。对未打开的项目按 `Delete`/`F8` 会删除上述全部内容，而不只是布局。如果项目有代理会话，会询问是否一并删除。目录已不存在的项目会在 `Projects` 菜单和切换器中标为 ✗。
- **`F1` 在窗口中打开帮助，并定位到当前聚焦面板的按键。** 帮助（`F1` / `Alt+H`、**选项 → 帮助**）现在是覆盖在面板之上的大窗口，而不再是挤进布局中的面板。它会打开到调用它的面板对应的章节，输入文字可筛选按键和描述，`Tab` / `Shift+Tab` 在章节之间切换，`F1` 或 `Esc` 关闭它。帮助面板已移除：关闭最后一个面板时，现在会在其位置留下一个位于项目根目录的文件管理器。参见[帮助窗口](https://github.com/termide/termide/blob/main/doc/zh/ui.md#帮助窗口)。
- **菜单打开时不选中任何项。** 菜单栏的下拉菜单、项目按钮的菜单、面板的 `[≡]` 菜单（`Alt+K`）、操作菜单和 stash 菜单打开时都不选中任何项，因此 `←`/`→` 在菜单栏上移动时不会途经 `AI → Agents` 或 `Options → Themes` 这样的子菜单。`↓` 选中第一项，`↑` 选中最后一项；在选中某项之前 `Enter` 不起作用，因此 `Alt+K Enter` 和 `F9 Enter` 现在需要先按一次 `↓`。从带 `▶` 的菜单项打开的子菜单仍从第一项开始。
- **`Projects` 成为最后一个菜单项。** 菜单栏现在依次为 `Bookmarks`、`Commands`、`Windows`、`Options`、`AI`、`Projects`，因此 `Projects` 菜单紧挨着已打开项目的按钮，`→` 可以从它直接移到这些按钮上。
- **AI → 会话列出会话所在的位置，涵盖每个项目以及项目之外。** 该部分此前只显示当前项目自身的会话，因此项目内部某个目录的会话、不属于任何项目的会话以及目录已被移走的会话都无法访问。现在它列出代理工作过的每个目录，最新的在前，路径前以暗色显示其最新会话的时间和会话数量，已不存在的目录标有 `✗`。`Enter` 在该目录打开一个代理面板，其横幅列出可恢复、重命名或删除的会话；对于已不存在的目录，它会询问目录现在的位置，并把会话连同其子目录的会话迁移过去，已保存布局中的代理面板也随之迁移。`Delete` 删除该目录的所有会话，在面板中打开的会话除外。
- **代理横幅显示会话数量。** 新代理面板的会话列表上方的标题显示它提供的会话数，`Sessions (42)`，在 `Ctrl+F` 搜索期间则显示匹配数与总数，`Sessions (3/42)`。

## 移除

- **`Projects` 菜单中的“更改根路径”已移除。** 它把当前项目指向另一个目录，只带上其布局。`F6`（**移动项目…**）会移动目录及 Termide 为其保存的一切；对于标有 ✗ 的项目（其目录已在 Termide 之外被移走），`F6` 会把它连同上述一切指向新位置，不移动任何文件。
- **已保存的布局不再按时间删除。** `project_retention_days` 设置及其在设置窗口中的字段已移除。项目保存的状态会一直保留，直到你从 `Projects` 菜单或切换器中将其删除（`Delete`/`F8`）。配置文件中残留的 `project_retention_days` 行会被忽略。
- **git 日志的 `C`“检出”键已移除，连同 `[git_log.keybindings]` 下的 `checkout` 设置。** 它只会提示检出尚未实现；分支在 git 状态面板中检出。
- **不再读取 shell 工具的旧名称 `bash`。** 0.49.0 把该工具重命名为 `shell`，并在 termide 自己保存的文件中改写了旧名称；项目自己的 `[ai.permissions]`、钩子或代理的 `tools:` 中残留的 `bash` 仅在该版本中仍然生效。现在它不对应任何工具，会作为未知工具名被报告——请将其重命名为 `shell`。

## 修复

- **从提交窗口提交会报告其哈希，并且 termide 保持响应。** “已提交”消息显示的是提交主题的最后一个词而不是哈希，而主题以 `исправлено` 这类词结尾时，termide 会在提交完成后立即崩溃。`git commit` 也曾在界面线程上运行，因此 pre-commit 钩子会让所有面板冻结直到它结束；现在提交在后台运行，状态栏显示 `Git commit...`，失败时显示 git 自己的消息。
- **使用 CRLF 换行的文件不再在编辑器边栏中显示每一行都已更改。** 以 CRLF 提交的文件一经编辑就会标记每一行，而从 LF 提交以 CRLF 检出的文件（`core.autocrlf`）从一开始就标记每一行；现在仅换行符不同不算更改。
- **在外部代理刚启动完成时发送的消息不再丢失。** 通过 ACP 使用 Claude Code、Codex 或 Gemini CLI 时，在代理会话打开那一刻到达的消息可能会立即结束其轮次而未被发送：面板显示运行已结束，而消息无处可去，直到你再发送一条。现在占用轮次和把消息加入队列是同时进行的，因此会话打开时消息已就位，重试失败的轮次时也同样如此。
- **分叉面板的计数保持可见。** 代理面板的标题会从末尾截断以适应宽度，这会把分叉名称中的计数截掉——`Refactor (2)` 和 `Refactor (3)` 都显示为 `Agent: Refactor…`。现在计数紧挨着标签，`Agent (2): Refactor`。
- **拒绝 Claude 推理字段的网关会收到不带这些字段的重发请求。** 拒绝 `thinking` 或 `output_config` 的 Anthropic 兼容端点会让每个请求都失败，而拒绝 `cache_control` 的端点此前就已经会收到不带该字段的重发请求。现在它点名拒绝的三者中任何一个，此后都会被省略，就像 OpenAI 兼容连接对它所添加的字段所做的那样。
- **无界面运行不再提供它无法使用的终端会话。** `termide --prompt` 向模型提供了 `terminals` 以及 `shell` 的 `session` 和 `background` 参数，但没有会话来持有它们的运行无法使用其中任何一个：每次这样的调用都会失败。现在那里不再提供它们，`shell` 的描述也不再提及它们。面板及其子代理仍保留它们。
- **语言服务器在大型 Go workspace 中正确启动。** termide 会询问工具链某个包的 workspace 从哪里开始；超过 64 KB 的回答（例如大型 `go.work` 上的 `go work edit -json`）会填满管道，工具一直挂起直到 3 秒的限制，服务器于是改在包目录启动。现在回答会边到达边读取。
- **输错的 `/command` 列出 `/` 所提供的命令。** 它列出的名称来自一份单独的列表，而这份列表已经偏离：它遗漏了 `/undo`，向无法运行 `/compact`、`/mcp` 和 `/trust` 的外部代理列出了它们，并在请求失败后漏掉了 `/continue`。现在内置命令位于一张表中，`/` 列表、这条提示以及相对于模板、脚本和技能的优先级都读取它。
- **能发现结巴的模型。** 循环保护此前只统计重复的句子，因此反复输出一小段内容（“PR PR PR …”）的模型会一直运行到输出上限；现在最后 2000 字节由一段不超过 64 字节的内容重复构成时也算作循环。
- **新会话保留已关闭的工具，适用于所有代理。** 在代理面板中开始的新会话会启用所有工具，尽管它保留了为会话授予的权限；现在它以上一个会话关闭的工具集开始，这些工具不进入其上下文，并记录在其日志中。Claude Code、Codex 和 Gemini CLI 与内置代理一样遵循工具列表：在第一个请求之前，关闭的工具或技能会离开代理的上下文，重新打开的会回来，代理会以新的工具集重新启动。
- **设置中留空或输错的数字字段保留其值。** 此前它会被保存为 `0`，这会关闭保险库的自动锁定（**VFS → 密码库自动锁定时间（分钟，0 = 从不）**），让每个远程连接立即超时，并让资源指示器在循环的每一轮都采样；超出字段范围的数字会回绕，因此 `65536` 保存为 `0`。现在连接超时无论在哪里设置都至少为一秒，设置窗口会让资源采样间隔至少为 100 毫秒、制表符宽度至少为 1。**日志 → 最小日志级别** 上的左右键现在也能到达 `trace`——列表提供了它，但方向键此前会跳过。
- **挂起任务的行不再看起来像暂停的会话。** 它在输入框上方的行带有 `⏸`，这是会话列表给留有待续工作的会话的标记；现在它带有 `↻`，与面板自身等待限额时一样。代理指南新增一张表，列出在对话之外运行的所有工作——由谁启动、它的行、什么会停止它、返回什么，以及什么限制它。
- **`termide --prompt` 接受以连字符开头的提示。** 以列表项开头的提示（`- keep the weights…`）此前被当作未知选项读取，运行根本没有开始。
- **被拒绝、被过滤或溢出的回答会如实说明。** 当 Claude 模型拒绝回答或用完其上下文窗口、OpenAI 兼容提供商的内容过滤器截断了回答，或 OpenAI 模型发送了拒绝时，该轮此前会像模型正常结束一样结束，常常没有任何内容。现在它以指明原因的错误结束。外部代理的拒绝也会如此说明，而此前在拒绝之前没有文本时，它会静默地结束该轮。
- **重新打开的会话即使从未切换过模式，也保留其工作时的模式。** 此前只有权限模式的切换才会写入会话日志，因此一直以配置模式运行的会话重新打开时——尤其是重启之后——会采用届时配置中的模式：把默认值改为 `plan`，所有这样的面板回来时都在做计划。现在每个请求都会记录发送时所用的模式。
- **触及输出上限却没有内容的回复不再结束运行。** 在工具调用结束前一直扣住它的服务器，对于卡在调用中的模型什么也不会发送，运行便在空回复上结束，仿佛模型已经回答。现在面板会发出警告，模型会得知情况并被要求采取更小的一步，第二次这样的回复或循环会停止运行。当用尽上限的是模型的推理时，下一次调用不带推理，就像循环之后那样：带推理重新请求时，模型又一次推理到了上限。
- **终端面板的标题会跟随退出的程序。** 在 `less`、`vim` 或其他程序退出后，标题可能一直保留其名称 `(less)`，直到有别的东西重绘屏幕。现在标题的变化本身就会重绘面板。
- **等待文本的终端 `send` 会报告该文本。** 当等待的文本和 shell 返回提示符同时到达时，调用可能回答命令已结束，而不是文本已出现；现在在报告结束之前会再检查一次文本。
- **不回应查询的终端不再让启动停顿数秒。** termide 此前逐个向宿主终端询问键盘协议和 emoji 宽度，每个问题最多等待两秒回复，因此保持沉默的终端或中继会让第一帧延迟约四秒——分离实例每次启动时询问会话守护进程也是如此。现在这些问题一起发出，终端对最后一个问题的回复结束等待，沉默的终端在一秒后放弃，分离实例则不询问任何问题，像以前一样从客户端获取答案。
- **服务器无法解析的工具调用不再结束运行。** 当 oMLX 无法读取模型写出的工具调用（JSON 损坏、参数被截断）时，它会以错误结束回复，内置代理随之停止。现在代理不运行该回复中的任何调用，告诉模型其调用格式错误并再请求一次；同一步中第二次出现这样的回复会像以前一样以该错误停止运行。
- **参数格式错误的工具调用会如实说明。** 当模型以损坏的 JSON 发送调用参数时，Anthropic 连接会不带参数运行工具，OpenAI 兼容连接则报告第一个参数缺失；无论哪种，模型得到的都是错误的信息，并以同样的方式再试。现在该调用不会运行，模型读到的是其参数不是有效的 JSON 对象，并附上它发送的内容。
- **崩溃的工具只让自己的调用失败。** 遇到内部错误的工具会拖垮代理的运行，或拖垮外部代理通过 termide 工具发起的调用，后者随后一直显示为运行中。现在该调用以模型可读的错误结果结束，运行继续进行。
- **外部代理因请求上限而停止的轮次会如实说明。** 当通过 ACP 的代理因达到自身的模型请求上限（`max_turn_requests`）而结束一轮时，该轮显示为已完成的回答；现在它以指明该上限的错误结束。
- **Alt 加字母能传到终端面板中的程序。** 没有 kitty 键盘协议时，终端面板把 `Alt+D` 作为普通的 `d` 发送，因此 readline 的 `kill-word`、`Alt+.`（上一个参数）、`Alt+Backspace` 和 Emacs 的 Meta 键都会输入一个字符。现在 Alt 会像其他终端一样在按键之前发送 Escape。在分离实例之外，`Alt+D` 不再停在“不是分离实例”上，也会传到 shell。
- **后台项目中的代理把规则授予其自身的项目。** 在代理卡片上回答“在此项目中始终允许”时，规则会保存到当时恰好是当前项目的那个项目。如果代理在后台打开的项目中工作，规则就会落到错误的项目。现在它会落到代理面板所属的项目。从代理批准项目命令时同样如此。
- **流中途被截断的回答会如实说明。** 当与 OpenAI 兼容服务器或 Anthropic API 的连接在模型表明回答完成之前关闭时，已到达的内容会被当作完整回答，包括写了一半的工具调用。现在该轮以“流在回答完成之前结束”结束；在任何内容到达之前就关闭的流会像其他断开的连接一样重新请求。
- **`auto_reviewer = "name"` 被读作它所指定的连接。** 这种字符串形式来自审查者还不能指定模型的时候，此前会被搁置并给出警告；现在它被读作该连接。
- **取消批量复制后会删除你选择的内容。** 取消多文件复制后，“删除已复制”什么也不做，而“保留已复制”会删除已经复制的文件；现在这两个按钮会照其所述执行。
- **Claude Code 在执行计划时不再以为自己仍处于计划模式。** 以计划模式开始的 Claude Code 会话会把计划指令永久保留在其系统提示中。只有一条说明表示该模式已关闭，而 Claude Code 的压缩可能会丢掉它。现在这些指令作为轮次之前的一条说明给出，从不放进系统提示，并且在压缩之后和恢复会话时会再次告知当前模式。计划卡片在 Claude Code、Codex 和 Gemini CLI 上也提供“并清理上下文”：它会启动该代理的一个新会话，并附上决定和计划的回顾。
- **由 `AGENT.md` 的 `command` 启动的 Claude Code 能获得 termide 的工具。** 以 `command: npx -y @agentclientprotocol/claude-agent-acp` 定义的代理，无论在面板中还是作为子代理，得到的是一个没有工具的 MCP 服务器，取代了它自己的工具，因此无法读取文件或运行命令；现在它得到的工具与 `claude_code` 连接的代理相同，以这种方式定义的 Codex 和 Gemini CLI 代理也能获得连接所提供的配套工具和 MCP 服务器的工具。
- **`Ctrl+F` 和 `Ctrl+P` 能传到终端中的全屏程序。** 即使在 `less`、vim、fzf 或 emacs 占据屏幕时，终端也会把 `Ctrl+F` 用于其查找栏，命令面板会占用 `Ctrl+P`，而这些程序用它们来翻页、补全或移动。现在备用屏幕开启时，这两个键都交给程序，而在 shell 提示符处它们仍会打开查找栏和命令面板。终端指南现在列出被全局操作占用的 readline `Alt` 键。
- **由系统信任的证书颁发机构签名的端点可以连接。** 模型连接、基于 HTTP 的 MCP 服务器和 `fetch` 此前只信任 termide 内置的证书，因此在企业 TLS 代理之后，或端点使用内部证书颁发机构时，每个请求都会以 `UnknownIssuer` 失败，只有重新构建才能解决。现在它们也信任系统的证书存储，并且可以用 `SSL_CERT_FILE` 或 `SSL_CERT_DIR` 指定颁发机构；系统证书存储缺失时仍使用内置的证书集。验证仍然无法关闭。
- **终端中的 `Esc` 交给 shell。** 在空闲的提示符处，`Esc` 既会传到 shell，又会请求关闭面板，因此 bash 或 zsh 的 vi 模式每按一次都会弹出对话框。现在运行中的终端把 `Esc` 交给其程序，并用 `Alt+W` 关闭；程序已结束的终端仍可用 `Esc` 关闭。
- **输入一半的 Vim 命令之后按 `Escape` 不再提议关闭编辑器。** 当有计数、操作符或 `g` 这样的前缀在等待时，`Escape` 会丢弃它，面板保持打开。
- **每个快捷键都在设置窗口中，并检查冲突。** `open_agent`（`Alt+A`）和编辑器的 `code_action`（`Alt+Enter`）在 **快捷键** 下没有对应的行，因此只能通过 `config.toml` 重新绑定；而绑定到查看器的 `Ctrl+E` 或 `Ctrl+L` 的编辑器按键（编辑器会先匹配后者）永远不会触发，也不会给出警告。现在两者都有对应的行，`[viewer.keybindings]` 也与其他部分一起检查。
- **FTP 列表保留含空格的名称和符号链接。** 含有多个连续空格的名称只剩下一个空格，符号链接被列为 `name -> target`，因此对它的每个操作都指向一个不存在的路径。现在删除目录时，会把其中的符号链接作为链接删除，而不进入其指向的内容。
- **高亮 Haskell 不再写入已释放的内存。** 一旦以严格别名（strict aliasing）编译其 C 代码（优化构建就是这样），Haskell 语法的扫描器会通过缓冲区增长之前的指针继续写入其前瞻缓冲区。编辑时重新解析 pragma（`{-# … #-}`）可能破坏内存或使 termide 中止，在 Linux 上 glibc 就会这样做。现在语法的 C 代码以 `-fno-strict-aliasing` 构建。AUR 源码包把它保留在 makepkg 自己的 `CFLAGS` 中，并在不使用 makepkg 的 LTO 的情况下构建，因为 LTO 会导致链接失败（未定义的 `tree_sitter_*` 符号）。
- **图标、日志和语言服务器在设置中更改后立即生效。** 图标模式、日志的最低级别和文件、启用或关闭 LSP，以及编辑语言服务器条目，此前都要重启后才生效，尽管设置窗口会立即应用每项更改。现在面板标题会立即更换图标，日志以新的级别写入新的文件，打开的编辑器会按配置连接到语言服务器：关闭 LSP 会停止服务器并清除其诊断，编辑某个条目只会重启该语言的服务器。
- **重新绑定的按键会显示在消息、帮助和面板菜单中，并且复制在所有地方都有效。** 重新绑定的全局 `copy` 在大纲、诊断、Markdown 和 HTML 查看器、Mermaid 和插件列表面板中不起作用，它们使用固定的 `Ctrl+C` 复制，帮助中也为它们和代理显示 `Ctrl+C`；“已在磁盘上修改”消息无论重新加载和另存为绑定到什么，都写着 `Ctrl+Shift+R` 和 `Ctrl+Shift+S`。现在它们都遵循快捷键设置。面板的 `[≡]` 菜单也会显示编辑器的暂存、取消暂存、还原、全部折叠和全部展开的按键，查找栏的匹配计数也使用界面语言。
- **复制和移动到服务器时会在覆盖前询问。** 把多个条目复制或移动到 SFTP 或 FTP 位置时，只有第一个条目会就服务器上已被占用的名称进行询问；其余的会覆盖已有内容，或针对恰好路径相同的本地文件进行询问。现在每个条目都会在服务器上查找，冲突对话框之后恢复的上传会正常上传而不是失败。在同一服务器内复制或移动的多个条目会全部完成，而不只是第一个。
- **`task` 如实描述 `background`。** 该参数的描述告诉模型后台任务在单独的面板中运行；实际上它在看不见的地方运行。
- **代理查看自己的终端时无需询问。** `terminals` 的列出、`read`、`screen`、`interrupt` 和 `close` 在 `all` 之外的所有模式下都会询问，而 `agents` 和 `debug` 会话的 `state` 在计划模式下会被拒绝，尽管两者都只读取：计划保护和各模式各自维护一份无需询问的调用列表，而两者已经偏离。现在一份列表同时服务于两者。
- **电池指示器跟随电池状态。** 此前只有在屏幕上其他内容变化时才会绘制新读数；现在只要任何指示器的读数会变化，菜单栏就会重绘。
- **命令面板的“打开偏好设置”打开设置窗口。** 它此前会在编辑器中打开 `config.toml`，而 `Alt+P` 和 **选项 → 设置** 打开的是设置窗口；现在三者行为一致。
- **数据库面板的“清除所有筛选”有了可用的按键。** 其默认的 `Alt+F` 同时也是全局的“新建文件管理器”，后者会先被匹配，因此该键会打开一个文件管理器。现在它是 `Shift+F3`，与 `F3` 筛选相邻；一项测试会确保每个面板的默认按键都不与全局按键冲突。
- **诊断面板高亮 `Enter` 将打开的那一行。** 启用“错误”或“警告”筛选时，高亮是按该行在未筛选列表中的位置绘制的，因此会落在另一行上或不落在任何行上，`Enter` 打开的诊断并不是高亮的那一个；更新还可能让选中位置超出筛选后的行。
- **无论你的 git 配置如何，diff 面板都读取 git 自己的补丁。** 当把 difftastic 这样的外部差异工具设为 `diff.external`、强制颜色（`color.diff = always`）或设置了 `diff.noprefix` 时，面板得到的是该工具的输出、转义码或不带前缀的路径，而不是补丁，于是什么也不显示或显示乱码。现在它对工作区、提交和 stash 的差异都会向 git 请求纯补丁。
- **编辑器的搜索键在其查找栏中按配置工作。** 查找栏获得焦点时，`F3` 和 `Shift+F3` 是固定按键，因此重新绑定的 `search_next` 或 `search_prev` 在那里不起作用，而 `Ctrl+R` 会重新执行搜索而不是 `replace_current`，尽管指南说替换键无论有没有查找栏都起作用。现在查找栏遵循编辑器的快捷键设置，替换处于活动状态时，`replace_current` 和 `replace_all` 可以从查找栏执行替换。
- **git 日志的按键遵循设置。** `[git_log.keybindings]` 下的 `info` 和 `view_diff` 会被读取但从不检查——`Space`、`d` 和 `Ctrl+R` 在代码中是固定的——因此重新绑定它们不起作用；现在它们可以正常工作，并新增了 `refresh`（`Ctrl+R`）。
- **Nix 包会安装 shell 补全。** `nix build` 和 `nix profile install` 现在会像 deb、rpm 和 AUR 包一样安装 bash、zsh 和 fish 的补全，并使用 `rust-toolchain.toml` 中固定的编译器构建，而不是 nixpkgs 自带的编译器。`nix build .#termide-static` 以本机架构为目标，而不再总是 x86_64。
- **展开的工具调用输出按面板宽度换行。** 命令输出、文件读取或编辑差异中的长行会超出代理面板的右边缘并在那里被截断；现在它会在后续各行中按其缩进继续显示，差异行在每一行上都保持其底色。
- **Vim 操作符可以向上作用以及作用到文件两端。** `dk` 和 `yk` 作用于上一行而不是下一行，`dG`、`dgg` 和 `d{number}G` 作用于直到文件末尾、开头或指定行的整行，`d0` 删除到行首而不是让 `d` 一直等待，删除最后一行后也不再在其位置留下一个空行。
- **消息、状态栏和大小遵循界面语言。** 编辑器、十六进制查看器、Markdown、HTML、图表、CSV 和图像查看器的状态栏，查找和替换栏，命令面板，跳转到行和重命名提示，取消复制和书签对话框，后台操作指示器（“Copying 40% (+2 queued)”），git push、pull 和 fetch 的通知，以及有关 stash、暂存、提交、删除、保存和重新加载、上传和远程复制、失败的操作、SSH 和 git 启动、获取的页面和图像、代码操作、插件和打开失败的消息，此前在所有语言中都是英文；十六进制查看器的错误和关闭提示，编辑器的强制保存、重新加载、复制和替换提示，Mermaid 面板关于它不绘制的图表的提示，“未找到引用”、文件管理器的“未找到匹配项”以及 git 面板的“已复制”提示也是如此；现在它们都遵循界面语言。git 面板属性中的文件大小，以及资源指示器的内存和磁盘数字，使用文件管理器早已使用的翻译后的单位。最近新增的约五十个标签和帮助行（例如命令设置和帮助中的按键描述）此前只翻译成了俄语，现在所有语言都有了翻译。一行粘贴的内容或一个复制的字符在德语、西班牙语、法语和葡萄牙语中以单数形式显示（“1 Zeile”、“1 carácter”），印尼语、德语、西班牙语、法语、葡萄牙语和俄语中遗留为英文的几个标签也已翻译。
- **保存时保持链接的 `config.toml` 仍为链接，并能写入命名管道或设备。** 设置保存时会写入固定的 `config.toml.tmp` 并将其重命名覆盖原文件，这会把符号链接（保存在 dotfiles 检出中的配置）替换为普通副本，在重命名之前没有同步数据，还会让同时进行的两次保存共用一个临时文件；编辑器的保存同样会把 FIFO 或设备节点替换为普通文件。现在编辑器、代理、项目存储和设置共用同一种原子写入：一个名称唯一、已同步的同级文件被重命名覆盖到链接的目标上，而普通文件之外的任何东西都原地写入。

## 安全

- **调试器不再在相对的 `PATH` 条目中查找。** 含有 `.` 或空条目的 `PATH` 会让 termide 在其启动目录（可能是某个项目的目录）中查找 `lldb-dap`、`gdb`、`dlv` 或 Python，并启动该项目以此名称放在那里的任何东西。现在只搜索绝对路径条目，与插件相同。
- **为会话允许一条发给另一个代理的消息，不再放行之后的所有消息。** 该回答此前被保存为针对该消息类型的规则，因此之后的每条 `info`、`question` 或 `reply` 都会不经询问地发往任何面板，无论内容是什么。现在在 `ask` 模式下，每次 `send_message` 都会询问，显示发给谁以及全部内容，并且不提供超出本次调用有效期的回答。参见[与其他面板通信](https://github.com/termide/termide/blob/main/doc/zh/agent.md#与其他面板通信)。
- **为会话允许一次 `terminals send`，不再放行之后的所有调用。** 该回答此前被保存为只针对 `send` 的规则，因此之后输入到代理任何终端中的任何按键都会不经询问地运行，绕过 `shell` 所经过的检查。现在在 shell 提示符处输入的完整一行会被当作它所运行的 `shell` 命令，按 `shell` 规则判断；其他任何 `send`——输入给程序的内容、编辑该行的按键——每次都会询问，显示它输入的全部内容，并且不提供超出本次调用有效期的回答。参见[终端会话](https://github.com/termide/termide/blob/main/doc/zh/agent.md#终端会话)。
- **命令钩子和会话的保护对子代理、无界面运行和被改写的调用同样有效。** `hooks.toml` 的钩子此前不会在面板子代理或 `termide --prompt` 的调用前后运行，因此可以通过委派调用来绕过保护钩子；现在它们在那里也会运行。子代理还能调用在“工具”菜单中关闭的工具，`/undo` 也不会恢复它更改的文件；现在它受面板工具集的约束，其编辑也会保留以供 `/undo`。钩子改写的参数会再次经过计划模式和会话中关闭的工具的检查，而此前经钩子批准的改写会跳过这些检查。没有读取大型工具结果任何内容的钩子不再让代理等待超过其超时时间。参见[钩子](https://github.com/termide/termide/blob/main/doc/zh/agent.md#钩子)。
- **权限卡片显示调用的作用，“始终允许”保存的是它所显示的规则。** 关于 MCP 工具的卡片此前只显示其中一个参数，而“始终允许”保存的是针对该参数值的规则；现在它显示全部参数，并按文档所述为该工具保存 `"*" = "allow"`。`task` 卡片除代理外还显示任务内容，针对会话的回答会信任该代理的任务；`fork` 卡片显示新面板将接手的工作；针对技能名称的规则对调用传入的任何参数都有效。在 `auto` 模式下，对于该模式会搁置的规则不再提供“始终允许”：该回答在会话期间有效。参见[MCP 服务器](https://github.com/termide/termide/blob/main/doc/zh/agent.md#mcp-服务器)。

## 性能

- **长代理会话不再在代理工作时拖慢面板。** 每一帧加载动画都会再次复制会话的每一行，答案的每个流式片段都会重新排版整个答案。现在每一帧只排版变化的部分：加载动画，或正在写入的块，对于答案则只排版自其最后一个完整段落或代码块以来新到的内容。在一个 2,000 个块的会话中，一帧加载动画从 0.8 毫秒降到几微秒，40 KB 答案流式输入时的一帧从 2.5 毫秒降到 0.3 毫秒。
- **终端的回滚缓冲只占用一小部分内存。** 其 10,000 行中的每一行此前都按屏幕宽度保存，包括空白单元格；现在每行只保存到其最后一个可见单元格。在 66 列宽的终端中，一万行 `seq` 此前占用 9.8 MB，现在占用 3.3 MB，全宽终端节省得更多。
- **空闲的 termide 不再为它不显示的数字重绘。** 每个使已用内存变化一兆字节的资源采样都会重绘整个屏幕，尽管菜单栏以 GB 显示它；现在只有当指示器的读数会变化，或时钟走过一分钟时，采样才会触发重绘。
- **进入重新打开的项目不再因其代理会话而停顿。** 项目加载时，其每个代理面板都会把该项目的每个会话日志完整读取两遍，因此首次切换到拥有数百个日志的项目时，屏幕会冻结好几秒。现在会话摘要——标题、日期、`⏸` 标记——在日志未变化时会保留在内存中以及日志旁边的 `summaries.json` 索引中，因此新的运行只读取此后有变化的日志；在 519 个日志（365 MB）上，启动后的第一次列出耗时 14 毫秒而不是 0.7 秒，占用 9 MB 内存而不是 140 MB。确实需要读取的日志会并行读取。
- **Linux 构建使用工具链自带的链接器。** 仓库不再强制使用 GNU `ld`：x86_64 使用 rust-lld（自 1.90 起为 rustc 的默认链接器），其他架构则像以前一样使用系统的 `ld`。链接二进制文件使用 GNU `ld` 约需 6.4 秒，使用 lld 则为 1.0 秒；对于从源码构建的打包者而言，唯一的区别是 x86_64 上的链接器。开发者指南说明了如何使用 mold。
- **一个加密库取代两个。** SFTP 的 SSH 此前运行在 aws-lc 上，而 FTP 和数据库的 TLS 运行在 ring 上；现在 SSH 也使用 ring，这使二进制文件减小 0.7 MB，构建 termide 也不再需要 cmake。已用 ChaCha20-Poly1305、AES-GCM 和 AES-CTR 加密算法以及 ed25519 和 RSA 密钥在 OpenSSH 上验证。
