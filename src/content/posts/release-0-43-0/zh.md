## 新增
- **断点与调试启动。** 在编辑器中按 `Ctrl+F8` 或单击行号，会在该行设置断点，以行号旁的 `●` 显示；在其上方增删行时，断点随其文本移动，并按文件保存，重启后依然存在。`F5` 在新的终端面板中启动命令行调试器，设置好项目的断点，并把程序运行到第一个断点处：`commands.toml` 中带有 `debugger = "lldb"`、`"gdb"`、`"dlv"` 或 `"pdb"` 的命令指定要调试的程序（可选的 `build` 会先运行），而 Python 或 Go 文件完全不需要命令。有多个启动项时以列表形式供选择。命令面板在任何面板中都提供 **开始调试** 和 **移除所有断点**，编辑器的 `[≡]` 菜单也是如此，调试命令在 命令 菜单中显示 🐞。
- **通过 DAP 在 TermIDE 内调试。** `debugger = "lldb-dap"`、`"gdb-dap"`、`"debugpy"` 或 `"dlv-dap"` 会驱动调试适配器，并在新的调试面板中显示会话：程序停在哪里、为何停下、调用栈、所选栈帧的变量（以按需展开的树显示）以及程序的输出。`c` 继续，`n`、`s` 和 `o` 分别单步跳过、单步进入和单步跳出，`p` 暂停，`x` 停止，`r` 重新运行启动项——先以相同参数运行其构建——`e` 对表达式求值；在编辑器中按 `F5` 也会继续。程序停下的行在编辑器的边栏中以 `→` 标记，并在单步执行时跟随，不会从面板夺走焦点；会话期间修改的断点会立即传给适配器。安装了相应工具时，Python 文件在 debugpy 下调试，Go 文件所在的包在 `dlv dap` 下调试，均无需命令。
- **代理驱动调试器。** 面板的代理获得 `debug`：它可以设置断点，启动调试命令或 Python、Go 文件，单步执行，选择栈帧并对表达式求值，每次回答都是以文本表示的会话——停在哪里、调用栈、变量和最近的输出。启动和单步会等待下一次停下。该会话就是调试面板中的那个会话，调试面板在其他面板旁打开且不夺取焦点，因此用户也可以观看并单步执行。在计划模式下只允许 `state`。
- **被调试的程序可以读取键盘输入。** 通过适配器调试的程序在调试面板旁自己的终端面板中运行，因此可以向它输入内容，其输出也像在任何终端中一样显示。debugpy 和 Delve 通过 `runInTerminal` 请求终端；lldb-dap 自己的终端启动器在 macOS 上会失败，因此通过 lldb 的 target 设置把它指向该面板的终端设备。在 `commands.toml` 中设置 `console = "panel"` 则让输出留在调试面板中，GDB 的适配器和代理的会话始终如此。

## 变更
- **排队的消息带有 `✕`。** 它在代理状态条中的那一行原本已显示等待了多久，现在与目标和循环的行一样以 `✕` 结尾；单击它会把队列取回输入框，与 `↑` 相同。
- **推理及其回传无需设置：由服务器决定。** 连接到 OpenAI、OpenRouter 或 Gemini API 的 OpenAI 兼容连接以 `reasoning_effort` 发送推理级别；其他任何服务器，无论地址为何，都会收到 `chat_template_kwargs.enable_thinking`，以及模型在当前轮次中的推理——自你上一条消息以来的回答，位于该轮的工具调用之间——以 `reasoning_content` 和 `reasoning`（Ollama 的 OpenAI 兼容层读取的字段，[ollama#18534](https://github.com/ollama/ollama/issues/18534)）回传，并附带 `preserve_thinking`，没有它，llama.cpp 的 Qwen 模板会丢弃这些推理。更早轮次的推理不再回传：它在每次请求中都消耗输入 token，而模型几乎用不上，Qwen 和 DeepSeek 的模板本身也会丢弃它。拒绝其中某个字段的服务器——返回 400 或 422 并指明 `chat_template_kwargs`、`reasoning_effort`、`return_progress`、`reasoning_content` 或 `reasoning`——会立即收到去掉该字段的同一请求，该服务器上的所有会话和附带调用都会省略该字段，直到 termide 重启，届时会再次询问可能已升级的服务器。
- **每个 cargo 或 Go 工作区只有一个语言服务器。** 作为上层 cargo 工作区成员的 crate，或列在 `go.work` 中的 Go 模块，过去会各自获得一个服务器，每个都重新加载同一个工作区；现在服务器在工作区根目录启动，所有成员共用一个。成员关系通过工具链查询——`cargo locate-project --workspace`、`go env GOWORK` 和 `go work edit -json`——而不是从清单中读取，每个包只查询一次；独立的 crate 或模块、位于某个工作区下但不是其成员的 crate 或模块，或者缺少相应工具时，仍像以前一样使用最近的标记。该查询绝不会触发工具链下载。

## 修复
- **代理运行的任何程序都无法接管 termide 的终端。** 代理的 `bash` 在独立的进程组中启动命令，但保留了 termide 的控制终端，因此它们运行的任何程序——调试器、`stty`、密码提示——都能打开 `/dev/tty` 并让 termide 退出 raw 模式：此后每个按键都会以转义码的形式显示在屏幕上并伴随响铃，任何快捷键都不起作用，连退出也不行。现在命令在独立的会话中运行，没有控制终端；请求控制终端的程序会得到一个错误，而不是 termide 的终端。
- **一个会话同一时间只在一个 termide 中运行。** 第二个 termide 打开同一个项目时——而第一个仍在一个被误关的终端窗口中运行，在看不见的地方继续存活——会把第一个正在进行的运行当作已中断的运行，提出继续它，于是同一个 Claude Code 会话运行了两次：两个代理写同样的分支、运行同样的检查，各自把对方当作陌生人。现在会话通过其日志旁 `.lock` 文件上的操作系统锁租给持有它的 termide，无论该 termide 以何种方式结束，操作系统都会释放这把锁。另一个 termide 以只读方式显示该会话，不启动代理，不发送也不提出任何东西，会写明持有它的进程，并在其被释放后接手。此前同一个 termide 的两个面板不会共用一个会话，但两个 termide 却会。
- **代理在等你时，`/goal` 会暂停而不是空转。** 评审有了第四种结论 `WAITING`：代理停在只有你或外部事件才能解决的事情上——一个问题、一项批准、一个它不会去碰的进程或另一个会话。此时目标会立即暂停并保持设置，与只说话的目标一样；此前它每一轮都被退回，代理用一次状态检查重申在等待，从而绕过了无工具计数，每次都耗费一整次模型调用，直到订阅额度用完。
- **模型编造的工具会在其块中显示名称。** 外部代理调用它没有的工具——用 `bash` 代替 `mcp__termide__bash`——会显示为 `other`，即 ACP 赋予它的类型；现在块中显示被调用的名称。
- **`send_message` 和 `agents` 的显示与其他工具一致。** 它们的块显示原始工具名和 JSON；现在显示为 `@ Writing to panel 7 · info: …` 和 `@ Listing agent panels`。
- **停止代理会交还其队列。** 代理工作时输入、在你停止它时仍在等待的消息，停止后仍留在状态条中，却没有任何东西发送它，直到 `↑` 把它取回或下一个请求把它带上；外部代理则会随被取消的轮次把它丢掉。现在停止会把队列放进输入框，排在已输入内容之前，由你发送或修改。
- **悬停弹窗渲染 Markdown。** gopls 的回答按原样显示其 ```` ```go ```` 围栏、各节之间的 `---` 以及行内标记的反引号和星号；现在 Markdown 悬停内容经过 Markdown 面板和代理对话记录所用的渲染器——代码块高亮并带竖条，分隔线显示为线，强调和行内代码带样式。纯文本悬停内容按原样显示。
- **制表符不再留下空洞。** 制表符被原样发送到终端，终端会把光标移到下一个制表位而不绘制内容，因此以制表符缩进的文本——悬停弹窗中的 Go 结构体、Markdown 和 HTML 面板或代理对话记录中的 Go 代码块——会出现空隙，其中残留着先前帧的内容。现在制表符会先展开为空格。

## 移除
- **连接设置 `reasoning_param` 和 `send_reasoning`**（连接页面上的 **推理参数** 和 **回传推理**）。它们手动选择的内容现在由服务器自己的回答决定，而它们的 `auto` 是根据主机名猜测的：名为 `.lan` 的服务器，或租用机器上的 llama.cpp，得不到推理开关和 `preserve_thinking`，因此会在一轮的各步骤之间丢弃模型的推理，模型便用一个刚刚编造的数字作答，而不是它思考过的那个（[#62](https://github.com/termide/termide/issues/62)）。仍然包含它们的配置可以正常加载；这些键会被跳过。
- **连接设置 `prefill_progress`**（**预填充进度（llama.cpp）**）。现在除托管 API 之外的每个服务器都会被请求提示词处理进度，因此 llama.cpp 服务器无需另行设置就会显示预填充进度条；拒绝 `return_progress` 的服务器会收到去掉该字段的同一请求，其他服务器则忽略它。仍然包含它的配置可以正常加载。

## 安全
- 将 `zip` 更新至 9.0，修复 RUSTSEC-2026-0367 至 0369：其 `extract()` 会保留 setuid 位，并跟随指向目标目录之外的链接。termide 用自己的代码解包 zip 归档，会把名称和链接限制在目标目录内，从未调用 `extract()`；此次更新是为了通过审计。
