你的 ChatGPT 套餐包含 Codex，机器上的 Codex CLI 也已登录。你可以在 termide 的某个终端面板里运行 `codex`，但它只是待在 termide 旁边，而不是融入其中：它的修改绕过打开的编辑器直接写入磁盘，确认提示是它自己的，会话也不属于 termide。

termide 的代理面板可以改为在 Codex 上运行。模型、套餐以及 Codex 自己的工作方式仍归 OpenAI；权限卡片、会话列表以及跟随每次修改的编辑器则归 termide。本指南介绍如何配置，以及与在终端中使用 Codex 相比有哪些不同。

## 准备工作

- **Node.js**，并且 `npx` 在 `PATH` 中。termide 通过 Codex 的 [Agent Client Protocol](https://agentclientprotocol.com) 适配器 `@agentclientprotocol/codex-acp` 驱动它，并用 `npx` 运行其最新版本。npm 缓存中的副本启动时不访问注册表；termide 每次运行时在后台检查一次新版本，新版本从下一个面板起生效。
- **已登录 Codex。** termide 本身不执行登录。如果你已经在用 Codex CLI，就无需再做什么；否则运行一次 `codex login`，用你的 ChatGPT 账号登录。也可以使用 API 密钥：在启动 termide 的环境中设置 `CODEX_API_KEY` 或 `OPENAI_API_KEY`。

## 添加连接

按 <Keys k="Alt+P" /> 打开设置，进入 **AI**。最上面是 **连接**。选择 **+ 添加连接**，在新连接的页面上把 **提供方** 设为 **Codex**。页面会去掉 Codex 用不到的字段——基础 URL、API 密钥、后备上下文窗口——在你命名之前，连接名为 `codex`。

<Shot src={models} alt="设置，AI › codex：提供方为 Codex，模型下拉列表展开：自动（由提供方决定）、gpt-6.1-sol (low)、gpt-6.1-sol (medium)、gpt-6.1-sol (high)、gpt-6-luna (low)、gpt-6-luna (medium) 和手动输入模型 id" caption="模型下拉列表列出你登录账号的模型，每个都带推理强度，显示 Codex 给它们的名称。" />

页面上的其余项：

- **模型**：termide 会短暂启动 Codex，列出你登录账号可用的模型；加载期间字段中显示旋转指示。Codex 为每个推理强度分别列出一次模型。**自动（由提供方决定）** 把选择留给 Codex。这里选的只是预选模型：在面板中随时可以切换。
- **上下文窗口上限**：留空则使用模型自身的窗口，也可以设得更小。Codex 通过 `CODEX_CONFIG` 以 `model_context_window` 接收它（你自己的 `CODEX_CONFIG` 会保留），并在达到其 90% 时压缩对话，面板的 `Context:` 也不会超过它。
- **默认使用**：勾选后，新的代理面板都会在 Codex 上启动。

在 `config.toml` 中写法相同：

```toml
[ai]
connection = "codex"         # 新会话使用的连接

[ai.connections.codex]
provider = "codex"           # 其他都不是必需的
# model = ""                 # 留空：使用 Codex 自己的默认模型
# context_window_limit = 200000
```

## 第一个请求

按 <Keys k="Alt+A" /> 打开代理面板。横幅显示连接和模型；Codex 在后台启动期间，状态栏的 **模型** 标签会旋转，此时发送的请求会等待它就绪。之后面板的工作方式与其他连接相同：回答、推理和 Codex 的步骤以块的形式出现——读取、带文件名的修改、带命令行的命令——打开了该文件的编辑器会跟随每次修改，运行计时一直走到 Codex 完成为止。

<Video src="/assets/blog/codex/codex.mp4" poster="/assets/blog/codex/codex.png" label="report.py 下方是连接 Codex 的代理面板：一个请求、一次读取、编辑器在第 14 和 15 行显示的修改、python3 -m unittest -q 的权限卡片（按 1 回答），然后是回答" caption="在 Codex 上发一个请求：编辑器标出改动的行，运行测试要等你回答。" />

这些标签可以随时切换 Codex 提供的选项，运行期间也可以：

- **模型**：你登录账号的模型，名称与 Codex 给出的一致。
- **推理**：推理强度。
- **选项**：它的其余设置。

Codex 自己的 `/` 命令会加入面板的 `/` 列表，按原样发送给它；它的 `/compact` 取代 termide 的同名命令。在它工作时输入的消息会并入正在进行的回合，与在 Codex 中一样。

## Codex 的工具，termide 的决定

与 Claude Code 不同，Codex 保留 **自己的系统提示词和自己的工具**：它像在终端中一样读取、修改和运行命令，它自己的配置——`~/.codex/config.toml`、它的 MCP 服务器、`AGENTS.md`——依然有效。termide 增加的是：

- **权限模式。** termide 让 Codex 进入与面板模式对应的模式，并由 termide 决定 Codex 请求确认的操作。
- **termide 的 MCP 服务器。** 它们的工具与 Codex 自己的工具一起提供给 Codex，并像 Codex 自己的调用一样接受检查。Codex 只在会话启动时读取一次工具列表，因此之后才连上的服务器要到下一个会话才可用。
- **Codex 没有对应物的工具**：用于搜索以往会话和 git 历史的 `recall`、在描述中列出你的技能的 `skill`，以及 `question` 和 `suggest_command`。

对话循环仍由 Codex 负责：它自己压缩上下文，运行也无法在步骤之间暂停。

## 权限与 auto 模式

**权限** 标签（或 <Keys k="Shift+Tab" />）设置模式，termide 把它映射到 Codex 的模式上：

| termide | Codex |
| --- | --- |
| `ask`、`configured`、`auto` | 只读，需要确认 |
| `plan` | 只读，并处于它的计划协作模式 |
| `edit` | 可写工作目录 |
| `all` | 完全访问 |

Codex 请求确认的一切都要经过 termide 的检查：你的规则、你在本会话中给出的答复，以及模式。它们未能决定的操作会以卡片形式出现在输入框上方：允许一次、本会话允许、在本项目中始终允许或处处允许、拒绝、拒绝并告诉代理原因，或停止运行。

<Shot src={permission} alt="输入框上方的卡片：代理想运行 python3 -m unittest -q，选项有允许一次、本会话允许、拒绝、本会话拒绝、拒绝并告诉代理原因、停止运行" caption="Codex 通过 termide 的卡片询问，和 termide 自己的代理一样。" />

`auto` 适用于你信任其方向、但不想一张张回答卡片的运行。本该弹出卡片的操作会交给审查模型——一次独立的模型调用，判断这一步是否服务于你的请求。在 Codex 连接上，审查 **通过你的套餐、在它提供的最便宜的模型上运行**——名称中含 `luna` 的第一个模型，没有则用含 `mini` 的——无需 API 密钥：termide 保持适配器运行，每次审查都在一个简短的独立会话中进行，不带工具，也不带代理的对话，因此代理永远不会评判自己。一次审查需要一秒或更久，并计入套餐额度。可以在连接页面的 **auto 模式审查模型** 或 `[ai.auto_reviewer]` 中指定其他审查者：

```toml
[ai.auto_reviewer]
connection = "codex"    # 留空：会话自己的连接
model = "mini"          # 该连接的某个模型，按 id、名称或其中一部分匹配
```

Codex 自己的自动审查不会被使用：每个请求都由 termide 的审查模型判断。

## 额度用完时

套餐时间窗口的额度用完后，运行会结束并弹出卡片。Codex 的适配器只在错误文本中说明额度何时重置（“try again at 3:00 PM”），termide 从中读出时间：

- **等到 15:00 再重试**，
- **立即重试**，
- **停止**（<Keys k="Esc" />）。

<Shot src={limit} alt="额度错误和卡片 Usage limit reached：15:00 重置（还有 4 小时 17 分），选项有等到 15:00 再重试、立即重试、停止" caption="限额用完：卡片倒数到重置时间。" />

对于无人值守的 `/goal` 或 `/loop`，把 **遇到限额或中断时**（`[ai]` 下的 `on_limit`）设为 `wait`，运行会等到重置后自行继续；`ask_else_wait` 会显示卡片，无人回应时则等待。这期间关闭 termide 也不会丢失任何东西：重新打开的会话会把卡片带回来。

如果不想等，可以准备第二个连接。卡片显示期间，状态栏的 **连接** 标签仍可点击：把会话切换过去，然后回答 **立即重试**。对话会一并带过去，另一个模型从 Codex 停下的地方接着做：

```toml
[ai.connections.codex]
provider = "codex"

[ai.connections.local]
provider = "openai_compatible"
base_url = "http://localhost:8080/v1"   # llama.cpp、Ollama、omlx…
```

## 委派任务

Codex 不运行 termide 的委派任务：它有自己的分工方式，其页面上的 **子代理** 显示 *(无)*。委派任务也不能在 Codex 上运行：这需要模型连接或 Claude Code。

## 会话与开销

会话日志记录 Codex 自己的会话，因此重新打开的面板会继续该会话，Codex 了解完整的对话。从其他连接切换到 Codex 的会话，会先收到此前对话的记录。`/goal` 的判定请求和 `/handoff` 的简报请求会发送到 Codex 会话的一个分叉中，之后关闭，因此对话本身保持不变。

**会话信息**（<Keys k="F3" /> 或 `/usage`）按花费者——对话、`auto` 审查等——和按模型细分 token 用量。Codex 单独统计推理，因此 **推理** 一行会显示输出中有多少用于思考。

## 须知

- **termide 不提供沙箱。** termide 的权限是一种控制手段，而不是隔离：你允许的操作以你的权限运行，范围以 Codex 自己的沙箱模式为限。
- **Claude Code 和 Gemini CLI 的接入方式相同**：`provider = "claude_code"` 或 `"gemini_cli"`。参见 [代理面板中的 Claude Code](/zh/blog/claude-code/) 和 [代理面板中的 Gemini CLI](/zh/blog/gemini-cli/)。
- **任何 OpenAI 或 Anthropic 兼容的 API 都可以作为备用连接**，额度用完时把会话切换过去：OpenAI、[OpenRouter](/zh/blog/openrouter/) 或 Anthropic 这样的托管 API，或你自己的服务器，使用 termide 自己的代理。[llama.cpp](/zh/blog/llama-cpp/) 和 [omlx](/zh/blog/omlx/) 是后者的两个例子。
- **详细说明** 见 [代理指南](https://github.com/termide/termide/blob/main/doc/zh/agent.md#配置模型)。
