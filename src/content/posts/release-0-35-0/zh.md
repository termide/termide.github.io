## 新增
- **图片查看器支持缩放。** 以前图片按原始尺寸绘制在面板左上角，只有放不下时才缩小，于是一个小图标孤零零地待在空面板的角落里，而照片也无法放大到超过面板允许的尺寸来细看。现在图片打开时会适应面板——在宽度或高度允许的范围内尽可能大，保持宽高比并居中——按 `+` / `-`、在面板上滚动鼠标滚轮，或点击状态栏中的 `[−]` `[+]` 按钮，都会围绕可见部分的中心缩放；方向键可平移放大后的图片，`0`（或 `Fit` 按钮）返回适应面板的视图。状态栏显示像素尺寸，以及相对于源像素的缩放百分比。只有可见区域会交给终端的图形协议，因此放大一张大照片只需裁剪而不必完整重新编码，放大后的像素也会清晰绘制而不是模糊的。
- **Shell 补全。** `termide --install-completions` 会把对应 `$SHELL` 中 shell 的补全脚本写到该 shell 查找它的位置：bash 和 fish 之后无需任何其他操作；对于 zsh，需要添加到 `~/.zshrc` 的那一行 `fpath` 会被打印出来而不是直接写入，因为它必须位于 `compinit` 之前，而 rc 文件归用户所有。`termide --completions bash|zsh|fish` 会打印脚本，供手动放置。加载后，它可以补全各个选项、`--log-level` 和 `--completions` 接受的取值，以及——在运行着多个分离会话的服务器上最重要的部分——`--attach` 之后的会话 id，这些 id 在按下 Tab 的那一刻从 `--list-sessions` 读取。这些脚本是手写的，存放在 `completions/` 中，因此打包者无需运行二进制文件就能安装它们；发布的 tarball 包含这些脚本，`.deb`、`.rpm` 和 AUR 包会将其安装到系统范围。灵感来自 [讨论 #45](https://github.com/termide/termide/discussions/45) 中分享的 bash 脚本。

## 变更
- **行号栏的宽度只与最后一行的行号一样宽。** 以前它为每个文件预留四个数字位，所以一个三行的文件在每个行号前都带着三列空白。现在行号栏只占用缓冲区行数所需的宽度——短文件一位数，10k 行以上与以前一样是五位——其余宽度留给文本。当缓冲区超过 9、99 或 999 行时，内容会右移一列；这是为了宽度而做的取舍，因为窄终端的每一行都能感受到宽度。
- **在 Git 状态 中按 Enter 和双击会打开文件。** 以前它们会暂存或取消暂存文件，于是在 termide 其他地方用来打开文件的操作，在这里却悄悄修改了索引。现在两者都会在编辑器中打开文件；暂存仍有自己的按键、标题栏按钮和弹出菜单。帮助面板中 Enter 的条目也已相应说明。
- **操作 面板的高度与其卡片一致。** 以前打开它会占用该列的平均份额——在单个编辑器旁边占一半，在全屏预设下占整列——而里面通常只有一张进度卡片。现在它只申请卡片恰好需要的行数，随着操作开始和结束而伸缩，最多不超过该列的一半（超出部分卡片可滚动），并在全屏预设下保持这个高度。手动调整其大小后，它会变为普通的固定高度，直到关闭为止。面板通过 `Panel` 契约中新增的 `height_mode` 声明这一点；其他所有面板仍像以前一样共享该列。

## 修复
- **当目录中大部分变更是新文件时，Git 状态 中的目录行会被标为新建。** 文件夹的颜色取其变更文件中最常见的状态，因此一个包含一个已修改文件和两个新文件的已有目录会变成绿色，仿佛刚刚创建一样，包含一个删除和两个新增的目录也是如此。现在只有当文件夹中所有变更都是新增时才显示为新建，所有变更都是删除时才显示为已删除；任何混合情况都意味着该文件夹原本就存在，显示为已修改，与文件管理器的嵌套状态一致。
- **Git 状态 中的目录行不按其内容着色。** 让文件夹显示其变更文件颜色的按目录汇总，只在折叠或展开文件夹时计算；刷新时重建的树不包含它，因此每次更新后目录都显示为普通文本颜色，直到切换某个目录为止。现在重建时会与可见行一起计算它，正如文件管理器的嵌套状态一直以来所做的那样。
- **未聚焦的 git 面板显示过时的内容。** 监视器和 git 的更新只会完整地发送给每列中聚焦的面板；其他面板都被“标记为过时”，在下次获得焦点时再追上——这是手风琴布局时期的规则，那时聚焦的面板是屏幕上唯一可见的面板。有了自由高度后，该列的其他面板也是可见的，因此编辑器旁边的 Git 状态 面板会更新标题中的计数（过时路径会刷新这些计数），但在被点击之前一直保留旧的文件树。现在更新会发送给每个显示内容的面板；只有折叠到仅剩标题栏的面板——由全屏预设或手动缩小导致——才会被标记为过时，并且一旦再次变大就会追上，无论是否获得焦点。Git 日志 和 Git 差异 以前每次获得焦点都会重新加载，现在只有在折叠期间确实收到更新时才重新加载；可见时的实时更新保持不变。
- **窗口 菜单的条目会打开相邻的条目。** 0.34.0 中的快捷键标注把 `打开…` 下方的分隔行从列表中去掉了，而分发器使用的行索引仍然把它计算在内，因此从 `终端` 往下，每个条目执行的都是上一个条目的操作，shell 选择器也从未出现。分隔行已恢复，并新增了一个测试将列表与索引绑定。
- **面板边框上和 TUI 应用内部残留的碎片。** 工作区中 `unicode-width` 的分支丢掉了 emoji 序列规则，因此 `✔️`、`⚠️`、`❤️`、肤色和 ZWJ emoji 被算作一列，而所有终端都把它们绘制为两列。ratatui 的帧差异比较随后会把该行其余部分移动一列且永不重绘，留下上一帧的碎片——`pi` 编辑器中穿过的一条边框线、面板边框上的一个多余单元格——直到其他内容触及这些单元格为止。该分支现在重新携带上游的表格和状态机，只保留当初创建它时所为的孟加拉语间距标记覆盖。变体选择符是终端之间唯一存在分歧的地方——Ghostty、WezTerm 和 iTerm2 把 `⏱️` 绘制为两列，而 alacritty 和 foot 等基于 `wcwidth` 的终端则保持一列——因此 termide 会在启动时询问宿主终端（对于分离会话，由 attach 客户端询问）并遵循其答复；日志 中会记录这一结果，`TERMIDE_VS16_WIDE=0|1` 可覆盖它。ratatui 的帧差异比较针对这类 emoji 有自己的变通做法——假设终端将其保持为窄字符，于是把它们后面的单元格显式写为空白——而在会将其加宽的终端上，这个空白会错后一列并使该行其余部分移位（`twoocolumnsswide`）；现在 termide 会在差异比较运行之前把这些单元格标记为跳过。
- **终端网格能够理解字符宽度了。** 宽字符（CJK、emoji）占两个单元格，组合重音符号和变体选择符附着在它们前面的字符上，肤色和 ZWJ 序列保持为一个字素簇。以前每个码点都恰好占一个单元格：一行带重音符号且已填满的全宽文本会折到额外的一行，并使 `pi` 这类差分渲染器失去同步，于是旧行在错误的位置被擦除，而光标在任何 emoji 之后都会偏移几列。现在擦除或覆盖宽字符的一半会删除整个字符，与终端的行为一致。
- **在 macOS 上打开包含大型仓库的会话后会卡顿数分钟。** 监视器为每个目录注册一个非递归监视，而 notify 的 FSEvents 后端在每次这样的调用时都会重建整个事件流——销毁线程、创建线程、对迄今为止的所有路径执行 `FSEventStreamCreate`——而且全部在主线程上。一个跟踪了 `node_modules`（约 2,500 个目录）的仓库会让 UI 冻结将近一分钟甚至更久。FSEvents 本身就是递归的，因此现在一个仓库只在其根目录上注册一个递归监视，来自被 `.gitignore` 忽略的子树的事件在到达时丢弃，而不是通过不订阅它们来实现。Linux 仍保留按目录遍历的 inotify 方式，在那里开销很小。
- **`\[` 和 `\]` 不再从终端输出中被剔除。** 它们曾被当作 bash 提示符标记，但 readline 会在任何内容到达终端之前就消耗掉它们；正则表达式、LaTeX 和转义后的 markdown 等程序输出会丢失这些字符，行末的反斜杠也会被扣留或丢弃。
